리팩터링 카탈로그

Martin Fowler의 Refactoring (2nd Edition)에서 엄선된 리팩터링 기법 카탈로그입니다. 각 리팩터링에는 동기, 단계별 메커니즘 및 예제가 포함됩니다.

"리팩터링은 그 메커니즘으로 정의됩니다. 즉, 변경을 수행하기 위해 따르는 정확한 단계의 시퀀스입니다." — Martin Fowler

이 카탈로그를 사용하는 방법

  1. 코드 스멜 참조를 사용하여 스멜을 식별합니다.
  2. 이 카탈로그에서 일치하는 리팩터링을 찾습니다.
  3. 메커니즘을 단계별로 따릅니다.
  4. 동작이 유지되는지 확인하기 위해 각 단계 후 테스트합니다.

황금률: 어떤 단계든 10분 이상 걸린다면, 더 작은 단계로 나눕니다.

가장 일반적인 리팩터링

메서드 추출 (Extract Method)

사용 시점: 긴 메서드, 중복 코드, 개념에 이름을 붙일 필요가 있을 때

동기: 코드 조각을 그 목적을 설명하는 이름의 메서드로 만듭니다.

메커니즘: 1. 무엇을 하는지 (어떻게 하는지가 아님) 나타내는 이름으로 새 메서드를 만듭니다. 2. 코드 조각을 새 메서드로 복사합니다. 3. 조각에서 사용되는 지역 변수를 찾습니다. 4. 지역 변수를 매개변수로 전달합니다 (또는 메서드 내에서 선언). 5. 반환 값을 적절히 처리합니다. 6. 원래 조각을 새 메서드 호출로 대체합니다. 7. 테스트합니다.

이전:

function printOwing(invoice) {
  let outstanding = 0;

  console.log("***********************");
  console.log("**** Customer Owes ****");
  console.log("***********************");

  // Calculate outstanding
  for (const order of invoice.orders) {
    outstanding += order.amount;
  }

  // Print details
  console.log(`name: ${invoice.customer}`);
  console.log(`amount: ${outstanding}`);
}

이후:

function printOwing(invoice) {
  printBanner();
  const outstanding = calculateOutstanding(invoice);
  printDetails(invoice, outstanding);
}

function printBanner() {
  console.log("***********************");
  console.log("**** Customer Owes ****");
  console.log("***********************");
}

function calculateOutstanding(invoice) {
  return invoice.orders.reduce((sum, order) => sum + order.amount, 0);
}

function printDetails(invoice, outstanding) {
  console.log(`name: ${invoice.customer}`);
  console.log(`amount: ${outstanding}`);
}

메서드 인라인 (Inline Method)

사용 시점: 메서드 본문이 이름만큼 명확할 때, 과도한 위임이 있을 때

동기: 메서드가 가치를 더하지 않을 때 불필요한 간접화를 제거합니다.

메커니즘: 1. 메서드가 다형적이지 않은지 확인합니다. 2. 메서드에 대한 모든 호출을 찾습니다. 3. 각 호출을 메서드 본문으로 대체합니다. 4. 각 교체 후 테스트합니다. 5. 메서드 정의를 제거합니다.

이전:

function getRating(driver) {
  return moreThanFiveLateDeliveries(driver) ? 2 : 1;
}

function moreThanFiveLateDeliveries(driver) {
  return driver.numberOfLateDeliveries > 5;
}

이후:

function getRating(driver) {
  return driver.numberOfLateDeliveries > 5 ? 2 : 1;
}

변수 추출 (Extract Variable)

사용 시점: 이해하기 어려운 복잡한 표현식이 있을 때

동기: 복잡한 표현식의 일부에 이름을 부여합니다.

메커니즘: 1. 표현식에 부작용이 없는지 확인합니다. 2. 불변 변수를 선언합니다. 3. 표현식 (또는 일부)의 결과로 설정합니다. 4. 원래 표현식을 변수로 대체합니다. 5. 테스트합니다.

이전:

return order.quantity * order.itemPrice -
  Math.max(0, order.quantity - 500) * order.itemPrice * 0.05 +
  Math.min(order.quantity * order.itemPrice * 0.1, 100);

이후:

const basePrice = order.quantity * order.itemPrice;
const quantityDiscount = Math.max(0, order.quantity - 500) * order.itemPrice * 0.05;
const shipping = Math.min(basePrice * 0.1, 100);
return basePrice - quantityDiscount + shipping;

변수 인라인 (Inline Variable)

사용 시점: 변수 이름이 표현식보다 더 많은 것을 전달하지 않을 때

동기: 불필요한 간접화를 제거합니다.

메커니즘: 1. 우측 변수에 부작용이 없는지 확인합니다. 2. 변수가 불변이 아니라면, 불변으로 만들고 테스트합니다. 3. 첫 번째 참조를 찾아 표현식으로 대체합니다. 4. 테스트합니다. 5. 모든 참조에 대해 반복합니다. 6. 선언과 할당을 제거합니다. 7. 테스트합니다.

변수 이름 변경 (Rename Variable)

사용 시점: 이름이 목적을 명확하게 전달하지 않을 때

동기: 좋은 이름은 깔끔한 코드를 위해 매우 중요합니다.

메커니즘: 1. 변수가 널리 사용되는 경우, 캡슐화를 고려합니다. 2. 모든 참조를 찾습니다. 3. 각 참조를 변경합니다. 4. 테스트합니다.

팁: - 의도를 드러내는 이름을 사용합니다. - 약어를 피합니다. - 도메인 용어를 사용합니다.

// Bad
const d = 30;
const x = users.filter(u => u.a);

// Good
const daysSinceLastLogin = 30;
const activeUsers = users.filter(user => user.isActive);

함수 선언 변경 (Change Function Declaration)

사용 시점: 함수 이름이 목적을 설명하지 않을 때, 매개변수 변경이 필요할 때

동기: 좋은 함수 이름은 코드를 자체 문서화합니다.

메커니즘 (단순): 1. 필요 없는 매개변수를 제거합니다. 2. 이름을 변경합니다. 3. 필요한 매개변수를 추가합니다. 4. 테스트합니다.

메커니즘 (마이그레이션 - 복잡한 변경의 경우): 1. 매개변수를 제거하는 경우, 사용되지 않는지 확인합니다. 2. 원하는 선언으로 새 함수를 생성합니다. 3. 이전 함수가 새 함수를 호출하도록 합니다. 4. 테스트합니다. 5. 호출자가 새 함수를 사용하도록 변경합니다. 6. 각 변경 후 테스트합니다. 7. 이전 함수를 제거합니다.

이전:

function circum(radius) {
  return 2 * Math.PI * radius;
}

이후:

function circumference(radius) {
  return 2 * Math.PI * radius;
}

변수 캡슐화 (Encapsulate Variable)

사용 시점: 여러 곳에서 데이터에 직접 접근할 때

동기: 데이터 조작을 위한 명확한 접근 지점을 제공합니다.

메커니즘: 1. getter 및 setter 함수를 생성합니다. 2. 모든 참조를 찾습니다. 3. 읽기를 getter로 대체합니다. 4. 쓰기를 setter로 대체합니다. 5. 각 변경 후 테스트합니다. 6. 변수의 가시성을 제한합니다.

이전:

let defaultOwner = { firstName: "Martin", lastName: "Fowler" };

// Used in many places
spaceship.owner = defaultOwner;

이후:

let defaultOwnerData = { firstName: "Martin", lastName: "Fowler" };

function defaultOwner() { return defaultOwnerData; }
function setDefaultOwner(arg) { defaultOwnerData = arg; }

spaceship.owner = defaultOwner();

매개변수 객체 도입 (Introduce Parameter Object)

사용 시점: 자주 함께 사용되는 여러 매개변수가 있을 때

동기: 자연스럽게 함께 속하는 데이터를 그룹화합니다.

메커니즘: 1. 그룹화된 매개변수를 위한 새 클래스/구조체를 생성합니다. 2. 테스트합니다. 3. 함수 선언 변경을 사용하여 새 객체를 추가합니다. 4. 테스트합니다. 5. 그룹의 각 매개변수에 대해 함수에서 제거하고 새 객체를 사용합니다. 6. 각 변경 후 테스트합니다.

이전:

function amountInvoiced(startDate, endDate) { ... }
function amountReceived(startDate, endDate) { ... }
function amountOverdue(startDate, endDate) { ... }

이후:

class DateRange {
  constructor(start, end) {
    this.start = start;
    this.end = end;
  }
}

function amountInvoiced(dateRange) { ... }
function amountReceived(dateRange) { ... }
function amountOverdue(dateRange) { ... }

함수들을 클래스로 결합 (Combine Functions into Class)

사용 시점: 여러 함수가 동일한 데이터에 대해 작동할 때

동기: 함수를 그들이 작동하는 데이터와 함께 그룹화합니다.

메커니즘: 1. 공통 데이터에 레코드 캡슐화를 적용합니다. 2. 각 함수를 클래스 안으로 옮깁니다. 3. 각 이동 후 테스트합니다. 4. 데이터 인수를 클래스 필드 사용으로 대체합니다.

이전:

function base(reading) { ... }
function taxableCharge(reading) { ... }
function calculateBaseCharge(reading) { ... }

이후:

class Reading {
  constructor(data) { this._data = data; }

  get base() { ... }
  get taxableCharge() { ... }
  get calculateBaseCharge() { ... }
}

단계 분리 (Split Phase)

사용 시점: 코드가 두 가지 다른 것을 다룰 때

동기: 코드를 명확한 경계를 가진 별개의 단계로 분리합니다.

메커니즘: 1. 두 번째 단계를 위한 두 번째 함수를 생성합니다. 2. 테스트합니다. 3. 단계들 사이에 중간 데이터 구조를 도입합니다. 4. 테스트합니다. 5. 첫 번째 단계를 자체 함수로 추출합니다. 6. 테스트합니다.

이전:

function priceOrder(product, quantity, shippingMethod) {
  const basePrice = product.basePrice * quantity;
  const discount = Math.max(quantity - product.discountThreshold, 0)
    * product.basePrice * product.discountRate;
  const shippingPerCase = (basePrice > shippingMethod.discountThreshold)
    ? shippingMethod.discountedFee : shippingMethod.feePerCase;
  const shippingCost = quantity * shippingPerCase;
  return basePrice - discount + shippingCost;
}

이후:

function priceOrder(product, quantity, shippingMethod) {
  const priceData = calculatePricingData(product, quantity);
  return applyShipping(priceData, shippingMethod);
}

function calculatePricingData(product, quantity) {
  const basePrice = product.basePrice * quantity;
  const discount = Math.max(quantity - product.discountThreshold, 0)
    * product.basePrice * product.discountRate;
  return { basePrice, quantity, discount };
}

function applyShipping(priceData, shippingMethod) {
  const shippingPerCase = (priceData.basePrice > shippingMethod.discountThreshold)
    ? shippingMethod.discountedFee : shippingMethod.feePerCase;
  const shippingCost = priceData.quantity * shippingPerCase;
  return priceData.basePrice - priceData.discount + shippingCost;
}

기능 이동 (Moving Features)

메서드 이동 (Move Method)

사용 시점: 메서드가 자신의 클래스보다 다른 클래스의 기능을 더 많이 사용할 때

동기: 함수를 가장 많이 사용하는 데이터와 함께 배치합니다.

메커니즘: 1. 메서드가 해당 클래스에서 사용하는 모든 프로그램 요소를 검사합니다. 2. 메서드가 다형적인지 확인합니다. 3. 대상 클래스로 메서드를 복사합니다. 4. 새 컨텍스트에 맞게 조정합니다. 5. 원래 메서드가 대상으로 위임하도록 만듭니다. 6. 테스트합니다. 7. 원래 메서드를 제거하는 것을 고려합니다.

필드 이동 (Move Field)

사용 시점: 필드가 다른 클래스에 의해 더 많이 사용될 때

동기: 데이터를 사용하는 함수와 함께 데이터를 유지합니다.
