name: claude-md description: 최적의 AI 에이전트 온보딩을 위한 베스트 프랙티스에 따라 CLAUDE.md 파일을 생성하거나 업데이트합니다.

사용자 입력

$ARGUMENTS

진행하기 전에 사용자 입력을 반드시 고려해야 합니다 (비어 있지 않은 경우). 사용자는 다음을 지정할 수 있습니다: - create - 처음부터 새로운 CLAUDE.md 생성 - update - 기존 CLAUDE.md 개선 - audit - 현재 CLAUDE.md의 품질 분석 및 보고 - 생성/업데이트할 특정 경로 (예: 디렉터리별 지침을 위한 src/api/CLAUDE.md)

핵심 원칙

LLM은 상태를 기억하지 못합니다(Stateless): CLAUDE.md는 모든 대화에 로드되는 핵심 프로젝트 파일입니다(자동 메모리 및 범위가 지정되지 않은 규칙과 함께 로드됩니다). 이는 AI 에이전트가 여러분의 코드베이스에 투입될 때 가장 먼저 읽는 핵심 온보딩 문서 역할을 합니다.

황금률

  1. 단순한 것이 더 좋습니다: 최첨단 LLM은 한 번에 약 150~200개의 지침을 따를 수 있습니다. Claude Code의 시스템 프롬프트가 이미 약 50개를 사용하고 있습니다. 여러분의 CLAUDE.md는 가장 핵심적인 내용에 집중하고 간결하게 유지해야 합니다.

  2. 보편적 적용 가능성: 모든 세션에 관련이 있는 정보만 포함하세요. 특정 작업에만 해당하는 지침은 별도의 파일로 분리해야 합니다.

  3. Claude를 린터(Linter)로 쓰지 마세요: 스타일 가이드라인은 컨텍스트를 비대화시키고 지침 준수 능력을 떨어뜨립니다. 대신 결정론적인 도구(prettier, eslint 등)를 사용하세요.

  4. 절대 자동 생성하지 마세요: CLAUDE.md는 AI 활용 효율을 극대화하는 가장 강력한 레버리지 포인트입니다. 신중하게 고민하여 수동으로 작성하세요.

실행 흐름

1. 프로젝트 분석

먼저, 현재 프로젝트 상태를 분석합니다:

  1. 기존 CLAUDE.md 파일이 있는지 확인합니다:
  2. 루트 레벨: ./CLAUDE.md or .claude/CLAUDE.md
  3. 디렉터리 특정: **/CLAUDE.md

  4. 글로벌 사용자 설정: ~/.claude/CLAUDE.md

  5. 프로젝트 구조를 파악합니다:

  6. 기술 스택 (언어, 프레임워크)
  7. 프로젝트 유형 (모노레포, 단일 앱, 라이브러리)

  8. 개발 도구 (패키지 매니저, 빌드 시스템, 테스트 러너)

  9. 기존 문서를 검토합니다:

  10. README.md
  11. CONTRIBUTING.md
  12. package.json, pyproject.toml, Cargo.toml 등

2. 콘텐츠 전략 (WHAT, WHY, HOW)

CLAUDE.md를 다음 세 가지 차원을 중심으로 구성하세요:

WHAT - 기술 및 구조

  • 기술 스택 개요
  • 프로젝트 구조 (특히 모노레포에서 중요)
  • 핵심 디렉터리 및 각각의 목적

WHY - 목적 및 맥락

  • 프로젝트가 하는 일
  • 특정 아키텍처 결정을 내린 이유
  • 각 주요 컴포넌트의 역할

HOW - 워크플로 및 관례

  • 개발 워크플로 (bun vs node, pip vs uv 등)
  • 테스트 절차 및 명령어
  • 검증 및 빌드 방법
  • 치명적인 '주의 사항(gotchas)' 또는 직관적이지 않은 요구사항

3. 점진적 공개 전략 (Progressive Disclosure)

프로젝트 규모가 큰 경우, agent_docs/ 폴더를 만드는 것을 권장합니다:

agent_docs/
  |- building_the_project.md
  |- running_tests.md
  |- code_conventions.md
  |- architecture_decisions.md

CLAUDE.md 안에서는 다음과 같은 지침으로 이 파일들을 참조하세요:

For detailed build instructions, refer to `agent_docs/building_the_project.md`

중요: 오래된 컨텍스트가 주입되는 것을 방지하기 위해 코드 스니펫(조각)을 복사해 붙여넣는 대신 파일명:줄번호(file:line) 참조를 사용하세요.

4. 품질 제약 조건

CLAUDE.md를 생성하거나 업데이트할 때:

  1. 목표 길이: 200줄 미만으로 유지합니다. 짧을수록 좋습니다.
  2. 스타일 규칙 배제: 린팅/포맷팅 지침은 모두 제거
  3. 작업 특정 지침 배제: 별도의 파일로 이동
  4. 코드 스니펫 배제: 대신 파일 참조를 사용
  5. 코드 스니펫 배제: package.json이나 README에 있는 내용을 반복하지 말 것

5. 필수 섹션

잘 구조화된 CLAUDE.md에는 다음 내용이 포함되어야 합니다:

# 프로젝트 이름

한 줄짜리 짧은 설명.

## 기술 스택
- 주요 언어 및 버전
- 핵심 프레임워크/라이브러리
- 데이터베이스/스토리지 (있는 경우)

## 프로젝트 구조
[모노레포 또는 복잡한 구조인 경우에만 작성]
- `apps/` - 애플리케이션 진입점
- `packages/` - 공유 라이브러리

## 개발 명령어
- 패키지 설치: `명령어`
- 테스트 실행: `명령어`
- 프로젝트 빌드: `명령어`

## 핵심 관례
[직관적이지 않고 영향력이 큰 관례만 작성]
- 관례 1과 짧은 설명
- 관례 2과 짧은 설명

## 알려진 문제 / 주의 사항 (Gotchas)
[개발자들이 지속적으로 실수를 범하는 부분들]
- 문제 1
- 문제 2

6. 피해야 할 안티 패턴

다음을 절대 포함하지 마세요: - 코드 스타일 가이드라인 (린터 사용하기) - Claude 사용법에 대한 문서 - 뻔하고 당연한 패턴에 대한 긴 설명 - 복사 붙여넣기 된 코드 예시 - 제네릭한 베스트 프랙티스 ("깨끗한 코드를 작성할 것" 등) - 특정 작업만을 위한 지침 - 자동 생성된 콘텐츠 - 광범위한 TODO 리스트

7. 검증 체크리스트

최종 확정하기 전에 확인하세요: - [ ] 200줄 미만으로 유지했는가? (짧을수록 좋음) - [ ] 모든 줄이 모든 세션에 보편적으로 적용되는가? - [ ] 스타일/포맷팅 규칙이 없는가? - [ ] 코드 스니펫이 없는가? (파일 참조 사용) - [ ] 명령어들이 실제로 작동하는지 검증되었는가? - [ ] 복잡한 프로젝트의 경우 점진적 공개 전략을 사용했는가? - [ ] 치명적인 주의 사항들이 문서화되었는가? - [ ] README.md와 중복되는 내용이 없는가?

출력 형식

create 또는 기본값의 경우:

  1. 프로젝트를 분석합니다.
  2. 위 구조에 따라 CLAUDE.md 초안을 작성합니다.
  3. 검토를 위해 초안을 제시합니다.
  4. 승인 후 적절한 위치에 파일로 기록합니다.

update 인 경우:

  1. 기존 CLAUDE.md를 읽습니다.
  2. 베스트 프랙티스를 기준으로 점검(Audit)합니다.
  3. 다음 사항을 식별합니다:
  4. 제거할 콘텐츠 (스타일 규칙, 코드 스니펫, 특정 작업용 지침)
  5. 압축할 콘텐츠
  6. 누락된 필수 정보
  7. 검토를 위해 변경 사항을 제시합니다.
  8. 승인 후 변경 사항을 적용합니다.

audit인 경우:

  1. 기존 CLAUDE.md를 읽습니다.
  2. 다음 내용이 포함된 보고서를 생성합니다:
  3. 현재 줄 수 vs 목표 줄 수
  4. 보편적으로 적용 가능한 콘텐츠의 비율
  5. 발견된 안티 패턴 목록
  6. 개선을 위한 권장 사항
  7. 파일을 수정하지 않고, 오직 보고만 수행합니다.

AGENTS.md 처리

사용자가 AGENTS.md 생성/업데이트를 요청하는 경우:

v2.1.277부터 Claude Code는 AGENTS.md를 프로젝트 지침으로 직접 읽습니다. 단, 작업 디렉터리와 그 상위의 모든 디렉터리에 CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md가 하나도 없을 때만 해당합니다. ~/.claude/CLAUDE.md, 관리형(managed) CLAUDE.md, .claude/rules/는 이 확인에 포함되지 않으며 계속 함께 로드됩니다. 어떤 파일을 읽을지는 /config의 Project instructions 항목으로 제어합니다: claude-md-or-agents-md(기본값), claude-md-and-agents-md, claude-md, managed-only. 직접 읽기를 사용할 수 없는 경우(v2.1.277 이전 버전(Bedrock/Vertex/Foundry, LLM 게이트웨이, 텔레메트리 비활성화 환경에서는 v2.1.281 이전), 또는 업그레이드 후 첫 세션)에는 CLAUDE.md에서 @AGENTS.md로 가져오거나 CLAUDE.md를 해당 파일에 대한 심볼릭 링크로 만드는 방식으로 대체합니다.

AGENTS.md는 여러 도구가 공용으로 쓰는 프로젝트 컨텍스트 파일로, 에이전트 정의 형식이 아니라 CLAUDE.md와 같은 종류의 문서입니다. 여러 코딩 에이전트가 하나의 프로젝트 규칙 세트를 공유할 수 있도록 존재합니다: - 빌드, 테스트, 린트 명령어 - 코드 스타일 및 아키텍처 규칙 - 저장소 구조와 각 항목의 위치

서브에이전트는 AGENTS.md가 아니라 .claude/agents/*.md에 별도로 정의합니다.

유사한 원칙을 적용합니다: - 핵심에 집중하고 간결하게 유지할 것 - 점진적 공개 전략을 사용할 것 - 콘텐츠를 직접 임베딩(포함)하는 대신 외부 문서를 참조할 것

참고 사항

  • 확실하지 않을 때는 제외하세요. 적을수록 좋습니다.
