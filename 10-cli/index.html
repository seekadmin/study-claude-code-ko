CLI 참조

개요

Claude Code CLI(명령줄 인터페이스)는 Claude Code와 상호 작용하는 주요 방법입니다. 이 CLI는 쿼리를 실행하고, 세션을 관리하며, 모델을 구성하고, Claude를 개발 워크플로에 통합하기 위한 강력한 옵션을 제공합니다.

아키텍처

graph TD
    A["User Terminal"] -->|"claude [options] [query]"| B["Claude Code CLI"]
    B -->|Interactive| C["REPL Mode"]
    B -->|"--print"| D["Print Mode (SDK)"]
    B -->|"--resume"| E["Session Resume"]
    C -->|Conversation| F["Claude API"]
    D -->|Single Query| F
    E -->|Load Context| F
    F -->|Response| G["Output"]
    G -->|text/json/stream-json| H["Terminal/Pipe"]

런타임 및 패키징

v2.1.113부터 Claude Code CLI는 선택적 npm 종속성을 통해 플랫폼별 네이티브 바이너리(macOS, Linux, Windows)를 시작합니다. 이 바이너리는 설치 시 운영체제 및 아키텍처에 맞춰지며, 이전 번들 JavaScript 런타임은 더 이상 macOS 또는 Linux의 기본값이 아닙니다.

권장 설치 방법은 네이티브 설치 프로그램입니다(curl -fsSL https://claude.ai/install.sh | bash, Windows에서는 irm https://claude.ai/install.ps1 | iex). 공식 README에서 npm 설치는 지원 중단(deprecated)되었으므로 네이티브 설치 프로그램, Homebrew(brew install --cask claude-code) 또는 WinGet(winget install Anthropic.ClaudeCode)을 사용하십시오. 참고로 npm install -g @anthropic-ai/claude-code(Node.js 22+)는 플랫폼별 선택적 종속성을 통해 동일한 네이티브 바이너리를 설치합니다.

다운로드 호스트 (v2.1.116+): 네이티브 바이너리 아티팩트는 https://downloads.claude.ai/claude-code-releases에서 제공됩니다.

기업 / 프록시 사용자: 네트워크에서 명시적인 허용 목록이 필요한 경우, downloads.claude.ai (및 https://downloads.claude.ai/claude-code-releases)를 프록시 egress 규칙에 추가하십시오. 이전에 storage.googleapis.com 또는 npm 레지스트리만 허용 목록에 추가했던 환경은 업데이트해야 하며, 그렇지 않으면 claude update 및 초기 설치가 실패합니다.

이전 JavaScript 번들은 Windows 및 해당 번들에 고정된 환경을 위해 여전히 생성됩니다. 이러한 설치는 Glob 및 Grep을 일등 도구로 계속 제공합니다(도구 및 권한 관리 섹션의 Glob/Grep 각주 참조).

CLI 명령

Command Description Example
claude 대화형 REPL을 시작합니다 claude
claude "query" 초기 프롬프트로 REPL을 시작합니다 claude "explain this project"
claude -p "query" 인쇄 모드 - 쿼리 후 종료합니다 claude -p "explain this function"
cat file \| claude -p "query" 파이프된 콘텐츠를 처리합니다 cat logs.txt \| claude -p "explain"
claude -c 가장 최근 대화를 계속합니다 claude -c
claude -c -p "query" 인쇄 모드에서 계속합니다 claude -c -p "check for type errors"
claude -r "<session>" "query" ID 또는 이름으로 세션을 재개합니다 claude -r "auth-refactor" "finish this PR"
claude update 최신 버전으로 업데이트합니다 claude update
/doctor (slash command) 설치, 구성 및 플러그인 상태를 진단합니다. v2.1.116부터 Claude가 응답 중일 때도 열 수 있으며, 상태 아이콘을 인라인으로 표시하고, 감지된 문제를 자동으로 해결하기 위해 f 키 입력을 받습니다. v2.1.178에서는 레이아웃이 더 명확한 상태 아이콘과 강조된 명령이 있는 평면 트리로 새로 고쳐졌습니다 REPL 내에서 /doctor를 실행합니다
claude mcp MCP 서버를 구성합니다 (인증을 위한 login/logout 포함, v2.1.186+). MCP 문서를 참조하십시오
claude mcp serve Claude Code를 MCP 서버로 실행합니다 claude mcp serve
claude agents 에이전트 뷰를 엽니다 (연구 미리보기, v2.1.139+) — 모든 Claude Code 세션을 상태와 함께 나열하는 다중 세션 관리자입니다. 아래 에이전트 뷰를 참조하십시오. claude agents
claude auto-mode defaults 자동 모드 기본 규칙을 JSON으로 출력합니다 claude auto-mode defaults
claude auto-mode reset 확인 프롬프트와 함께 기본 자동 모드 구성을 복원합니다 (--yes로 건너뛰기) (v2.1.212) claude auto-mode reset --yes
claude remote-control 원격 제어 서버를 시작합니다 (서버 모드, 로컬 대화형 세션 없음; 여러 세션 제공, --capacity 기본값 32) claude remote-control --name "My Project"
claude --remote-control [name] 원격 제어가 활성화된 대화형 세션을 시작합니다 (별칭 --rc) claude --rc
claude plugin 플러그인을 관리합니다 (설치, 활성화, 비활성화) claude plugin install my-plugin
claude plugin init <name> ~/.claude/skills/<name>/(사용자 전역)에 새 플러그인을 스캐폴딩합니다 — 다음 세션에서 <name>@skills-dir로 자동 로드되며 마켓플레이스가 필요 없습니다 (v2.1.157+) claude plugin init my-plugin
claude plugin tag [path] [path]의 플러그인에 대해 {name}--v{version} 릴리스 git 태그를 생성하며, plugin.json과 이를 포함하는 마켓플레이스 항목이 일치하는지 검증합니다 (v2.1.118+) claude plugin tag ./my-plugin
claude install [version] 특정 네이티브 바이너리 버전을 설치합니다. stable, latest 또는 명시적인 버전 문자열을 받습니다 claude install 2.1.131
claude purge [path] 프로젝트의 모든 로컬 Claude Code 상태를 삭제합니다 (대화 기록, 작업, 디버그 로그, 파일 편집 기록, 프롬프트 기록 및 ~/.claude.json 항목). 대화형 선택기를 사용하려면 [path]를 생략하십시오. 플래그: --dry-run으로 미리보기, -y/--yes로 확인 건너뛰기, -i/--interactive로 각 항목 확인, --all로 모든 프로젝트 (v2.1.126+) — v2.1.288에서 claude project purge에서 이름이 바뀌었으며, 이전 이름도 여전히 작동하고 안내 메시지를 출력합니다 claude purge ~/work/repo --dry-run
claude plugin prune 고아 상태의 자동 설치 플러그인 종속성을 제거합니다 (부모 플러그인 없음). plugin uninstall --prune은 대상 제거 후 동일한 연쇄 제거를 수행합니다 (v2.1.121+) claude plugin prune
claude ultrareview [target] /ultrareview를 비대화형으로 실행합니다. 결과를 표준 출력으로 출력하고, 성공 시 0, 실패 시 1, Ctrl-C로 중단 시 130을 반환합니다. 원시 페이로드를 위해서는 --json을, 45분 기본값(v2.1.260부터)을 재정의하려면 --timeout <minutes>를, 발견 사항을 PR에 게시할지 제어하려면 --post / --no-post를 사용하십시오. 신뢰하지 않은 폴더에서는 터미널이면 묻고, 그렇지 않으면 1로 종료합니다. 스크립트와 CI에서는 대상 뒤에 --trust-workspace를 덧붙이십시오 (v2.1.309+). Claude Code v2.1.227 이상 필요 claude ultrareview 1234 --json --no-post
claude self-hosted-runner [setup\|doctor\|orchestrator] 자신의 머신이나 컨테이너에서 Claude Code 클라우드 세션을 호스팅하는 러너를 시작합니다. setup은 운영자용 안내 절차, doctor는 배포된 러너 진단, orchestrator는 필요 시 러너를 생성합니다(--shutdown-drain-sec, v2.1.299는 SIGTERM 시 진행 중인 폴링과 생성 훅이 끝나도록 합니다). Team 및 Enterprise 플랜, Claude Code v2.1.224 이상 필요. Windows에서는 시작 시 명시적인 --base-dir이 필요합니다 (v2.1.229). v2.1.307부터 체크아웃 훅은 기본적으로 30분 후 중지되어 세션 설정이 실패하므로, --checkout-hook-timeout-min을 늘리거나 0으로 설정하십시오 claude self-hosted-runner setup
claude auth login 로그인합니다 (--email, --sso 지원). v2.1.126부터 브라우저 콜백이 로컬호스트에 도달할 수 없을 때 (WSL2, SSH, 컨테이너) 터미널에 붙여넣은 OAuth 코드를 폴백으로 받습니다 claude auth login --email user@example.com
claude auth logout 현재 계정에서 로그아웃합니다 claude auth logout
claude auth status 인증 상태를 확인합니다 (로그인되어 있으면 0, 아니면 1을 반환) claude auth status

핵심 플래그

Flag Description Example
-p, --print 대화형 모드 없이 응답을 출력합니다 claude -p "query"
-c, --continue 가장 최근 대화를 로드합니다 claude --continue
-r, --resume ID 또는 이름으로 특정 세션을 재개합니다 claude --resume auth-refactor
-v, --version 버전 번호를 출력합니다 claude -v
--system-prompt-snapshot off 대화와 함께 기록된 프롬프트를 재사용하지 않고 매 요청마다 시스템 프롬프트를 새로 렌더링합니다. 프롬프트 텍스트를 반복 수정할 때 유용합니다 (v2.1.257+) claude --system-prompt-snapshot off
-w, --worktree 격리된 git 워크트리에서 시작합니다. v2.1.233부터 GitHub PR URL뿐 아니라 GitLab 머지 리퀘스트 URL도 받습니다 claude -w
-n, --name 세션 표시 이름 claude -n "auth-refactor"
--from-pr <url-or-number> 풀/머지 요청에 연결된 세션을 재개합니다. v2.1.119부터 GitHub (클라우드 + 엔터프라이즈), GitLab MR, Bitbucket PR URL을 받습니다; 이전에는 GitHub.com만 가능했습니다 claude --from-pr 42 or claude --from-pr https://gitlab.example.com/org/repo/-/merge_requests/17
--cloud [description\|session_id\|url] 주어진 설명으로 claude.ai에 클라우드 세션을 생성하거나, 세션 ID 또는 claude.ai/code URL로 기존 세션에 연결합니다 claude --cloud "implement API"
--remote "task" --cloud의 지원 중단된 별칭(기존 세션 형식 포함). 대신 --cloud를 사용하십시오 claude --remote "implement API"
--remote-control, --rc 원격 제어를 통한 대화형 세션 claude --rc
--teleport [session] 웹 세션을 로컬에서 재개합니다. 인수 없이 쓰면 웹 세션 선택기가 열리고, 세션 ID를 전달하면 해당 세션을 바로 재개합니다. claude.ai 구독이 필요합니다 claude --teleport
--teammate-mode 에이전트 팀 표시 모드 claude --teammate-mode tmux
--bare 최소 모드 (훅, 스킬, 플러그인, MCP, 자동 메모리, CLAUDE.md 건너뛰기) claude --bare
--safe-mode 모든 사용자 정의를 비활성화한 상태로 시작하여 (CLAUDE.md, 플러그인, 스킬, 훅, MCP) 구성 문제를 격리합니다; CLAUDE_CODE_SAFE_MODE=1도 가능합니다 (v2.1.169) claude --safe-mode
--restricted 신뢰할 수 없거나 공유된 용도로 세션을 잠급니다: 내장 명령·코드 실행 도구와 WebFetch를 제거하고, 사용자/프로젝트/로컬 설정을 무시하며, 파일 도구를 작업 디렉터리로 제한하고, bypassPermissions와 클라우드 세션을 거부합니다. CLAUDE_CODE_RESTRICTED=1도 가능합니다 (v2.1.248+) claude --restricted -p "summarize this repo"

제한 모드 (--restricted, v2.1.248+)

--restricted(또는 CLAUDE_CODE_RESTRICTED=1)는 입력을 통제할 수 없는 사람을 대신해 claude를 실행할 때 사용합니다. 예를 들어 공유 머신의 평가 하네스, 외부 기여자가 트리거하는 CI 작업, 데모용 머신 등입니다. 다음을 모두 적용합니다.

  • 명령이나 코드를 실행하는 도구를 제거합니다 — Bash, PowerShell, REPL과 WebFetch. 단, --tools에 명시적으로 지정하면 제외됩니다.
  • 사용자, 프로젝트, 로컬 설정 파일을 무시합니다. 관리형 설정과 명시적인 --settings 파일은 계속 적용되므로, 관리자는 통제권을 유지하고 저장소에 체크인된 .claude/settings.json은 샌드박스를 넓힐 수 없습니다.
  • 파일 도구를 작업 디렉터리로 제한하므로, 읽기와 쓰기가 시작한 경로를 벗어날 수 없습니다.
  • bypassPermissions를 거부합니다(어떤 방식으로 요청하든).
  • 클라우드 세션 생성을 거부하므로, 제한된 실행이 작업을 머신 밖으로 보낼 수 없습니다.
# 평가 하네스: 셸 없음, 네트워크 가져오기 없음, 설정 상속 없음
claude --restricted -p "summarize the architecture of this repo"

# 같은 잠금 상태에서 도구 하나만 의도적으로 다시 활성화
claude --restricted --tools WebFetch -p "check the linked RFC"

참고: --restricted는 --permission-mode보다 더 거친 잠금입니다. 도구에 대해 프롬프트를 띄우는 대신 도구를 아예 제거하므로, 제한된 세션은 세션 내부에서 넓힐 수 없습니다.

게이트웨이 모델 탐색 (v2.1.129+, 선택 사항): ANTHROPIC_BASE_URL이 Anthropic 호환 게이트웨이를 가리킬 때, CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1을 설정하여 게이트웨이의 /v1/models 엔드포인트에서 /model을 채웁니다. 환경 변수가 없으면 /model은 내장된 정적 목록으로 폴백합니다. 이 플래그는 사용자가 사용할 권한이 없는 모델을 발견할 수 있기 때문에 선택 사항입니다 (v2.1.129에서 변경됨). v2.1.126에서는 암묵적이었으며 해당 동작은 되돌려졌습니다.

사용자 지정 base URL 뒤의 1M 컨텍스트 (v2.1.285): ANTHROPIC_BASE_URL이 사용자 지정 엔드포인트를 가리키는 세션은 이제 1M 컨텍스트 창을 가진 모델(Opus 4.7+, Sonnet 5+, Fable)에서 이를 사용합니다. 게이트웨이가 200K까지만 지원한다면 /autocompact 200k를 실행하십시오.

서드파티 제공자에서 기본 1M 컨텍스트 (v2.1.287): Opus 4.7+와 Fable은 이제 Amazon Bedrock, Google Vertex AI, Microsoft Foundry, Claude apps 게이트웨이에서 [1m] 접미사 없이 기본적으로 1M 컨텍스트 창을 사용합니다. 200K로 유지하려면 CLAUDE_CODE_DISABLE_1M_CONTEXT=1을 설정하십시오.

조직 기본 모델 (v2.1.196): 조직 관리자가 기본 모델을 설정하면 /model에 "Org default"(또는 "Role default")로 표시됩니다.

v2.1.111 업데이트: --enable-auto-mode는 제거되었습니다. 이제 자동 모드는 기본적으로 Shift+Tab 순환에 포함되며, 바로 자동 모드로 시작하려면 --permission-mode auto를 사용하십시오.

Glob / Grep 각주 (v2.1.113+): 네이티브 macOS/Linux 빌드에서는 Glob 및 Grep이 별도의 일등 도구가 아닌 Bash 도구를 통해 호출되는 내장 bfs 및 ugrep 바이너리로 제공됩니다. Windows 및 npm 번들(JS) 설치는 여전히 이를 독립형 도구로 노출합니다. 서브에이전트 allowedTools / disallowedTools 목록의 경우 백엔드 대체는 투명합니다. 모든 플랫폼에서 Glob / Grep을 구성에서 계속 참조할 수 있습니다.

PowerShell 자동 승인 (v2.1.119): PowerShell 도구 명령은 Bash 명령과 동일한 방식으로 권한 모드에서 자동 승인될 수 있습니다. Bash(...) 규칙에 이미 사용하고 있는 것과 동일한 매처 구문을 사용하여 PowerShell 권한의 범위를 지정하십시오. 예를 들어, PowerShell(Get-ChildItem:*)과 같습니다.

재개 시 --permission-mode 적용 (v2.1.132+): claude -p --continue --permission-mode plan (및 --resume)은 이제 이 플래그를 존중합니다. 이전 버전에서는 세션을 재개할 때 --permission-mode를 자동으로 삭제하여, 플래그를 다시 전달하지 않고 재개된 계획 모드 세션이 자동으로 다운그레이드되는 문제가 있었는데, 이는 해결되었습니다.

권한 강화 (v2.1.214): 데몬 리디렉션 플래그(예: --url, --connection, --identity)를 사용하는 Docker/Podman 명령은 이제 자동으로 실행되지 않고 권한 프롬프트가 필요합니다. -m/--magic-file 또는 -f/--files-from을 사용하는 file 명령도 권한이 필요합니다. 10,000자를 넘는 Bash 명령은 허용 규칙과 관계없이 항상 권한을 요청합니다.

권한 예시

# 코드 검토를 위한 읽기 전용 모드
claude --permission-mode plan "review this codebase"

# 안전한 도구로만 제한
claude --tools "Read,Grep,Glob" -p "find all TODO comments"

# 프롬프트 없이 특정 git 명령 허용
claude --allowedTools "Bash(git status:*)" "Bash(git log:*)"

# 위험한 작업 차단
claude --disallowedTools "Bash(rm -rf:*)" "Bash(git push --force:*)"

매개변수 일치 Tool(param:value) (v2.1.178): 권한 규칙은 Tool (모든 사용) 또는 Tool(specifier) 형식을 따릅니다. v2.1.178부터 지정자는 명령 또는 경로 패턴뿐만 아니라 와일드카드 지원을 통해 도구의 입력 매개변수와도 일치할 수 있습니다(Tool(param:value) 형식 사용). 이는 Bash(...) 명령 접두사(예: Bash(npm run test *)) 및 Read(...) 경로 glob(예: Read(./.env.*))에 이미 사용하는 일치 방식을 일반화하여 다른 도구도 인수에 따라 범위가 지정될 수 있도록 합니다. 규칙을 작성하기 전에 도구별 예시 문자열은 정확한 매개변수 이름이 도구마다 다르므로 권한 참조를 확인하십시오.

에이전트 구성

--agents 플래그는 세션을 위한 사용자 정의 서브에이전트를 정의하는 JSON 객체를 받습니다.

v2.1.243부터 --agents는 잘못된 JSON이나 잘못된 에이전트 정의를 조용히 무시하지 않고, --mcp-config와 마찬가지로 명확한 오류와 함께 종료합니다.

에이전트 JSON 형식

{
  "agent-name": {
    "description": "Required: when to invoke this agent",
    "prompt": "Required: system prompt for the agent",
    "tools": ["Optional", "array", "of", "tools"],
    "model": "optional: sonnet|opus|haiku"
  }
}

필수 필드: - description - 이 에이전트를 언제 호출할지 설명하는 자연어 설명 - prompt - 에이전트의 역할과 동작을 정의하는 시스템 프롬프트

선택 필드: - tools - 사용 가능한 도구 배열 (생략 시 모든 도구 상속) - 형식: ["Read", "Grep", "Glob", "Bash"] - model - 사용할 모델: sonnet, opus, 또는 haiku

완전한 에이전트 예시

{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",

    "model": "sonnet"
  },

    "description": "Debugging specialist for errors and test failures.",

  },
  "documenter": {
    "description": "Documentation specialist for generating guides.",

}

에이전트 우선순위

여러 에이전트 정의가 존재하는 경우 다음 우선순위 순서로 로드됩니다: 1. CLI 정의 (--agents 플래그) - 세션별 2. 프로젝트 수준 (.claude/agents/) - 현재 프로젝트 3. 사용자 수준 (~/.claude/agents/) - 모든 프로젝트

CLI 정의 에이전트는 세션에 대해 프로젝트 및 사용자 에이전트 모두를 재정의합니다. 프로젝트 수준 에이전트는 이름이 충돌할 때 사용자 수준 에이전트를 재정의합니다. 플러그인 수준 에이전트를 포함한 전체 우선순위 표는 레슨 04 — 서브에이전트를 참조하십시오.

  run: claude ultrareview ${{ github.event.pull_request.number }} --trust-workspace --json --no-post > review.json

claude ultrareview는 발견 사항 유무와 관계없이 검토가 완료되면 0을 반환하고, 시작 실패·오류·시간 초과·폴더 미신뢰 시 1을 반환하며, 검토 시작 중이나 발견 사항 대기 중, 또는 --post 댓글 게시 중에 Ctrl-C를 누르면 130을 반환합니다. 따라서 PR 게이트는 종료 코드가 아니라 review.json의 발견 사항을 기준으로 판단하십시오. CI에서는 체크아웃을 신뢰하는지 물을 수 없으므로, v2.1.309부터는 PR 번호나 기준 브랜치 뒤에 --trust-workspace(값 없음)를 전달하거나 작업 환경에 CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1을 설정하지 않으면 Error: Workspace not trusted와 함께 1로 종료합니다. 둘 다 신뢰할 수 있는 체크아웃에서만 사용하십시오. 45분 기본값(v2.1.260부터)을 재정의하려면 --timeout <minutes>를 사용하십시오. --post는 완료된 발견 사항을 풀 리퀘스트에 게시하고, --no-post는 표준 출력에만 남깁니다. 이후 CI 단계에서 보고서를 직접 포맷할 때 --no-post를 사용하십시오.

  "is this code secure?" < code.py)
if echo "$RESULT" | jq -e '.structured_output.secure == false' > /dev/null; then
  echo "Security issues found!"
  echo "$RESULT" | jq '.structured_output.issues[]'
fi

jq를 사용하여 Claude의 JSON 출력을 파싱하고 처리합니다. 응답 텍스트는 .result에 있으며, --json-schema를 사용하면 검증된 객체는 .structured_output에 있습니다(아래의 $SCHEMA는 각 필터가 읽는 필드를 정의한 스키마를 뜻합니다):

# 여러 필드 추출
claude -p --output-format json --json-schema "$SCHEMA" "describe the project" | jq -r '.structured_output | {name, version, description}'

# CSV로 변환
claude -p --output-format json --json-schema "$SCHEMA" "list functions" | jq -r '.structured_output.functions[] | [.name, .lineCount] | @csv'

# 조건부 처리
claude -p --output-format json --json-schema "$SCHEMA" "check security" | jq 'if (.structured_output.vulnerabilities | length) > 0 then "UNSAFE" else "SAFE" end'

# 중첩 값 추출
claude -p --output-format json --json-schema "$SCHEMA" "analyze performance" | jq '.structured_output.metrics.cpu.usage'

# 전체 배열 처리
claude -p --output-format json --json-schema "$SCHEMA" "find todos" | jq '.structured_output.todos | length'

# 출력 변환
claude -p --output-format json --json-schema "$SCHEMA" "list improvements" | jq '.structured_output.improvements | map({title: .title, priority: .priority})'

노력 수준 (Opus 5 / Sonnet 5 / Opus 4.8 / Opus 4.7)

Opus 5, Sonnet 5, Opus 4.8, Opus 4.7은 가장 가벼운 것부터 가장 무거운 것까지 low (○), medium (◐), high (●), xhigh, max 순서로 노력 수준을 가진 적응형 추론을 지원합니다. Opus 5.5, Sonnet 5.5, Haiku 5.5도 다섯 가지 수준을 모두 지원합니다. 기본값은 Opus 5.5(v2.1.280부터 기본 모델), Sonnet 5.5, Haiku 5.5에서는 medium, Opus 5, Sonnet 5, Opus 4.8(v2.1.154부터), Opus 4.6, Sonnet 4.6에서는 high, Opus 4.7에서는 xhigh입니다. xhigh는 Opus 5.5, Sonnet 5.5, Haiku 5.5, Opus 5, Sonnet 5, Opus 4.8, Opus 4.7에서 사용할 수 있습니다. max는 Opus 5.5, Sonnet 5.5, Haiku 5.5, Opus 5, Sonnet 5, Opus 4.8/4.7/4.6 및 Sonnet 4.6 (세션 전용)에서 작동합니다. Haiku 4.5에는 노력 수준이 없습니다. Opus 4.6 / Sonnet 4.6의 경우 Pro/Max 구독자의 기본 노력은 v2.1.117에서 medium에서 high로 상향 조정되었습니다.

# CLI 플래그를 통해 노력 수준 설정
claude --effort high "complex review"

# 슬래시 명령을 통해 노력 수준 설정
/effort high

# 환경 변수를 통해 노력 수준 설정
export CLAUDE_CODE_EFFORT_LEVEL=high   # low, medium, high, xhigh (Opus 5.5, Sonnet 5.5, Haiku 5.5, Opus 5, Sonnet 5, Opus 4.8/4.7), 또는 max — 기본값은 Opus 5에서 high

프롬프트의 "ultrathink" 키워드는 깊은 추론을 활성화합니다. /effort 슬라이더에는 Ultracode 토글(Tab 또는 /effort ultracode [on|off])도 있는데, 이는 모델 노력 수준이 아니며 세션의 노력 수준과 관계없이 Claude가 동적 워크플로를 오케스트레이션하도록 합니다. v2.1.284부터 더 이상 xhigh를 강제하지 않으며 수준을 바꿔도 켜진 상태로 유지됩니다. --effort ultracode와 Agent SDK의 effortLevel: "ultracode"는 여전히 xhigh를 설정합니다.

이 여덟 행은 변경 로그를 출처로 합니다. CLI 참조 페이지에는 별도의 환경 변수 섹션이 없으므로, 이 행들은 참조 페이지가 아니라 v2.1.221–v2.1.234 변경 로그 항목을 기준으로 문서화했습니다.

v2.1.223에서 범위가 넓어진 CLAUDE_CODE_DISABLE_1M_CONTEXT: 이제 고정된 모델 ID 목록뿐 아니라 네이티브 1M 토큰 창을 가진 모든 Claude 모델을 자동 압축으로 200K에 묶어 둡니다.

Agent Platform(Vertex AI) 및 게이트웨이의 ENABLE_TOOL_SEARCH: v2.1.221 이전에는 ENABLE_TOOL_SEARCH=true를 설정하지 않으면 Google Cloud's Agent Platform에서 도구 검색이 꺼져 있었습니다. 이제 그곳에서도 Claude Opus 4.5, Sonnet 4.5, Haiku 4.5 이후 모델에 대해 켜져 있습니다(이전 모델은 모든 MCP 도구를 미리 로드하며, true로도 바뀌지 않습니다). 도구 검색은 기본적으로 켜져 있으며, v2.1.304부터 사용자 지정 ANTHROPIC_BASE_URL 게이트웨이 뒤에서도 마찬가지입니다(v2.1.305부터 400 또는 422로 거부하는 게이트웨이는 도구 검색 없이 재시도). 모든 도구를 미리 로드하려면 ENABLE_TOOL_SEARCH=false로 설정하십시오.

프로젝트 설정의 OpenTelemetry 변수 (v2.1.282): 프로젝트 및 로컬 설정은 내보내기를 켜거나, 엔드포인트를 설정하거나, 콘텐츠를 캡처하는 OpenTelemetry 변수(예: CLAUDE_CODE_ENABLE_TELEMETRY, OTEL_LOG_*)를 무시합니다.

문제 해결

명령을 찾을 수 없음

문제: claude: command not found

해결책: - Claude Code 설치: curl -fsSL https://claude.ai/install.sh | bash(네이티브, 권장) 또는 npm install -g @anthropic-ai/claude-code - PATH에 ~/.local/bin(네이티브 설치) 또는 npm 전역 bin 디렉터리가 포함되어 있는지 확인 - claude doctor 실행

API 키 문제

문제: 인증 실패

해결책: - API 키 설정: export ANTHROPIC_API_KEY=your-key - 키가 유효하고 충분한 크레딧이 있는지 확인 - 요청된 모델에 대한 키 권한 확인

세션을 찾을 수 없음

문제: 세션을 재개할 수 없음

해결책: - 사용 가능한 세션 목록을 확인하여 올바른 이름/ID 찾기 - 세션은 비활동 기간 후 만료될 수 있음 - -c를 사용하여 가장 최근 세션 계속

출력 형식 문제

문제: JSON 출력이 잘못됨

해결책: - --json-schema를 사용하여 구조 강제 적용 - 프롬프트에 명시적인 JSON 지침 추가 - --output-format json 사용 (프롬프트에서 JSON을 요청하는 것만으로는 부족)

권한 거부

문제: 도구 실행이 차단됨

해결책: - --permission-mode 설정 확인 - v2.1.302부터 권한 모드를 지정하지 않은 claude -p 또는 Agent SDK 실행은 Manual 모드(구성 값 default)로 시작하며 승인이 필요한 도구 호출을 거부합니다. --permission-mode(예: auto 또는 acceptEdits)나 --allowedTools를 전달하십시오. - --allowedTools 및 --disallowedTools 플래그 검토 - 자동화를 위해 --dangerously-skip-permissions 사용 (주의 요망)
