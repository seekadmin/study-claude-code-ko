[v2.1.245] — 2026-08-25

Claude Code v2.1.245 기준 문서 동기화

Claude Code가 v2.1.235(2026-08-19)에서 v2.1.245(2026-08-25)로 10개 릴리스만큼 올라갔습니다. 이 항목은 해당 동기화를 기록합니다.

참고: 이 변경 로그에는 v2.1.233 및 v2.1.235 동기화(커밋 deb7e5c, da6e09e) 항목이 없습니다. 두 커밋은 변경 로그 항목 없이 저장소에 반영되었습니다. 날짜를 재구성해 소급 기재하지 않고 이 공백을 여기에 기록합니다.

수정됨

  • 버전 최신성 표기가 오래되었고 서로 모순됨 — 루트 README.md는 한 곳에서는 v2.1.235, 다른 곳에서는 v2.1.220 (July 2026)이라고 했고, 이 변경 로그의 최상단 항목은 여전히 v2.1.220을 현재 Claude Code 릴리스라고 했습니다. 이제 모두 v2.1.245로 표기합니다.
  • 훅 기본 타임아웃을 command, http, mcp_tool에 대해 60초에서 600초로 수정했고(prompt는 30, agent는 60), 이벤트별 재정의도 문서화했습니다.
  • 스킬 우선순위를 enterprise > personal > project로 수정했습니다. 레슨에서 project와 personal이 뒤바뀌어 있어 자체 퀴즈와 모순되었습니다.
  • 메모리 파일은 재정의되지 않고 연결됨 — 02-memory/README.md에 남아 있던 "overrides root CLAUDE.md" 문구 두 개를 교체했습니다.
  • SECURITY.md 가 더 이상 "1.x releases" 지원을 표기하지 않습니다.
  • STYLE_GUIDE.md 가 더 이상 예시로 오래된 푸터를 안내하지 않습니다.
  • 채점 자료(lesson-quiz 및 self-assessment 스킬)를 채점 대상 레슨과 다시 일치시켰습니다. 훅 이벤트 31개, 훅 유형 5개, 되감기 옵션 6개, 권한 모드 6개, 가져오기 깊이 4입니다.

추가됨

  • WebSocket(ws) MCP 전송 — 네 번째 전송 방식으로, .mcp.json 또는 claude mcp add-json으로 구성합니다.
  • Concise 출력 스타일 — 다섯 번째 기본 제공 스타일입니다(v2.1.237).
  • 새 설정 키 — modelPicker, promptCacheTtl, subagentPromptCacheTtl, modelPricing, keybindingFlavor.
  • ANTHROPIC_DEFAULT_MODEL 환경 변수(v2.1.236).
  • /design — 디자인 캔버스 리서치 프리뷰입니다.
  • 세션 간 SendMessage의 notify_when_idle (v2.1.236).
  • 플러그인 매니페스트 필드 — workflows, channels, dependencies 및 관련 CLI 추가 사항.

변경됨

  • Remote Control이 리서치 프리뷰를 벗어났습니다. 이제 claude remote-control을 실행 중인 머신이 Claude 앱에 디바이스 카드로 표시됩니다.
  • Ctrl+L 은 화면을 지우지 않고 다시 그립니다(v2.1.238).
  • 플러그인 commands/ 는 레거시로 표시되었으며, 현재 권장 방식은 skills/입니다.

[v2.1.220-r2] — 2026-08-04

Claude Code v2.1.220 기준 정확성 점검 (업스트림 버전 변경 없음)

v2.1.220(2026-07-25)이 여전히 현재 Claude Code 릴리스이므로, 이 항목은 버전 동기화가 아니라 내부 수정 사항을 기록합니다. 공식 문서를 기준으로 감사한 결과 누락된 업스트림 기능은 없었으며, v2.1.218–v2.1.220의 모든 기능이 이미 문서화되어 있었습니다. 대신 동작하지 않는 예시 코드, 파일 간에 서로 다른 개수와 이름, 메타데이터 불일치가 발견되었습니다.

수정됨

  • 06-hooks/pre-commit.sh가 실제로는 커밋을 차단하지 못함 — 스크립트가 네 곳에서 "Commit blocked."를 출력한 뒤 exit 1로 종료했습니다. 이 저장소의 종료 코드 표(06-hooks/README.md)에 따르면 exit 1은 차단하지 않는 오류이므로 커밋이 그대로 진행되었습니다. 차단하는 것은 exit 2뿐입니다. 네 곳 모두 이제 exit 2로 종료하고 차단 사유를 stderr에 씁니다. Claude Code는 차단 사유를 stderr에서 읽습니다.
  • 06-hooks/dependency-check.sh가 한 번도 실행되지 않음 — 대상을 $1에서 읽었지만 훅은 stdin으로 JSON을 받으므로 경로가 항상 비어 있었고 스크립트가 즉시 종료되었습니다. 이제 format-code.sh와 같이 stdin에서 file_path를 파싱합니다.
  • claude_concepts_guide.md에서 중첩 서브에이전트 깊이를 5로 표기 — "up to 5 levels deep as of v2.1.172"라고 적혀 있어, 다른 네 파일에 이미 문서화된 깊이 3 기본값(v2.1.219)과 모순되었습니다. 현재 동작을 먼저 설명하고 04-subagents/README.md와 같은 세 시기 이력 참고를 덧붙이도록 다시 작성했습니다.
  • 다섯 파일에서 훅 이벤트 수가 29개로 표기됨 — README.md, CATALOG.md, QUICK_REFERENCE.md(4곳), INDEX.md, resources.md가 모두 29라고 했지만, 공식 훅 목록과 이름 단위로 대조한 정확한 수는 31입니다. 이전 동기화에서는 두 파일만 고치고 나머지를 놓쳤습니다. README.md의 이벤트 목록은 25개, INDEX.md는 29개만 나열했으나 이제 둘 다 31개를 모두 나열합니다.
  • /less-permission-prompts는 실제 명령어가 아님 — 기본 제공 명령어는 /fewer-permission-prompts입니다. CATALOG.md는 한 파일 안에서 두 이름을 모두 사용했습니다.
  • /fork와 /subtask의 의미가 뒤바뀌어 문서화됨 — 두 명령어는 v2.1.212에서 역할을 맞바꿨습니다. 이제 /fork는 대화를 새로운 독립 백그라운드 세션으로 복사하고, 포크된 서브에이전트 동작은 /subtask로 옮겨졌는데 /subtask는 저장소에 전혀 없었습니다. 네 파일에서 수정·추가했습니다.
  • 08-checkpoints/README.md가 cleanupPeriodDays를 유일한 체크포인트 설정이라고 주장 — fileCheckpointingEnabled(기본값 true)도 존재하며, CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING과 체크포인트 100개 보존 상한도 있습니다. 저장소 자체의 config-examples.json은 이미 존재하지 않는다고 한 그 키를 사용하고 있었습니다.
  • 03-skills/refactor/SKILL.md가 refactor/에 있으면서 name: code-refactor로 선언 — 지난 동기화에서 doc-generator에 대해 고친 것과 같은 결함입니다. 영어 사본에서 이름을 바꾸고 ja/, zh/, uk/, vi/에도 반영했습니다.
  • 03-skills/README.md가 스킬 우선순위를 서로 모순되는 두 방식으로 설명 — 한 곳에서는 "enterprise > personal > project", 다른 곳에서는 "project wins by default"라고 했습니다. 이제 일관되게 enterprise > project > personal입니다.
  • claude-md 스킬이 AGENTS.md를 잘못 설명 — 에이전트 정의 형식이라고 했습니다. AGENTS.md는 여러 도구에서 쓰는 프로젝트 컨텍스트 파일이며, Claude Code는 이를 직접 읽지 않습니다. @AGENTS.md로 가져오거나 심볼릭 링크를 걸어야 합니다.
  • 02-memory/directory-api-CLAUDE.md가 루트 CLAUDE.md를 "재정의한다"고 주장 — 메모리 파일은 연결될 뿐 재정의되지 않습니다.
  • INDEX.md가 auto와 dontAsk를 거꾸로 설명 — dontAsk를 허용적인 모드("위험한 것 외에는 모두 수락")로 설명했지만, 실제로는 사전 승인되지 않은 모든 것을 자동 거부하는 가장 제한적인 모드입니다. 공식 정의로 수정했습니다.
  • permissions.mode는 설정 키가 아님 — 09-advanced-features/README.md와 claude_concepts_guide.md의 구성 예시 네 개가 이 키를(대체된 값 default와 함께) 사용했습니다. 이제 모두 permissions.defaultMode: "manual"을 사용합니다.
  • 09-advanced-features/config-examples.json에 Opus 5가 없음 — v2.1.219부터 Opus 5가 기본 Opus인데도 세 개의 "most capable" 프로필에 여전히 claude-opus-4-8을 사용했습니다.
  • 05-mcp/database-mcp.json에 자격 증명이 하드코딩됨 — postgresql://user:pass@localhost/mydb로, 모듈 자체의 "자격 증명을 하드코딩하지 말 것" 규칙과 모순되었습니다. 이제 ${DATABASE_URL}입니다.
  • 05-mcp/README.md가 MCP 범위는 문서화했지만 --scope 플래그는 설명하지 않음 — 독자가 실제로 범위를 선택할 방법이 없었습니다. 예시와 함께 추가했습니다.
  • /output-style이 지원 중단으로 표기됨 — 실제로는 v2.1.91에서 제거되었습니다. 출력 스타일은 /config 또는 outputStyle 설정으로 계속 사용할 수 있습니다.
  • 훅 permissionDecision에 defer가 빠져 있음 — 허용되는 값은 allow, deny, ask, defer이며 우선순위는 deny > defer > ask > allow입니다.
  • 컨텍스트 추적 훅이 128k 창을 가정 — 현재 Claude 모델 중 그런 모델은 없습니다. 기본값을 1M으로 올리고 Haiku 4.5의 200k를 함께 표기했습니다.
  • claude_concepts_guide.md의 로컬 메모리 경로가 잘못됨 — .claude/local/CLAUDE.md를 ./CLAUDE.local.md로 수정했습니다.
  • 03-skills/doc-generator/SKILL.md의 깨진 펜스 — 바깥쪽 ```markdown 블록이 일찍 닫히면서 닫히지 않은 펜스가 남아, 예시의 절반이 실제 마크다운으로 렌더링되었습니다. 이제 백틱 네 개짜리 바깥 펜스를 사용합니다. check_markdown_rendering.py가 README 파일만 검사하기 때문에 어느 검증기도 이를 잡아내지 못했습니다.
