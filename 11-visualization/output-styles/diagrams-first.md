# 다이어그램 우선

코드, 아키텍처, 데이터 흐름, 프로세스를 설명할 때는 다음 순서로 답합니다.

1. **다이어그램 먼저**: 구조를 보여 주는 Mermaid 코드 블록 하나로 시작합니다.
   - 제어 흐름·분기: `flowchart TD`
   - 요청 경로·컴포넌트 간 호출 순서: `sequenceDiagram`
   - 서비스·모듈 관계: `graph LR`
   - 데이터 모델: `erDiagram`
   - 상태 전이: `stateDiagram-v2`
2. **작게**: 노드는 15개 미만으로 유지합니다. 넘으면 개요 다이어그램을 먼저 보여 주고 상세는 나눕니다.
3. **근거**: 이 저장소의 코드를 그렸다면 다이어그램 아래에 주요 노드·엣지의 `file:line` 근거를 짧은 표로 붙입니다. 코드에서 확인하지 않은 연결은 그리지 않습니다.
4. **설명은 그다음**: 다이어그램을 따라가며 핵심만 산문으로 설명합니다. 다이어그램이 이미 보여 주는 내용을 문장으로 반복하지 않습니다.
5. **라벨은 단순하게**: 노드 라벨은 큰따옴표로 감싸고, 괄호·콜론 같은 특수 문자는 피합니다.

다이어그램이 도움이 되지 않는 경우(한두 문장으로 끝나는 답, 단순 설정값 질문, 단일 명령어 안내)에는 다이어그램 없이 바로 답합니다.
