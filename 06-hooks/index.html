훅

훅은 Claude Code 세션 중 특정 이벤트에 반응하여 실행되는 자동화 스크립트입니다. 훅을 사용하면 자동화, 검증, 권한 관리, 사용자 정의 워크플로를 구현할 수 있습니다.

개요

훅은 Claude Code에서 특정 이벤트가 발생할 때 자동으로 실행되는 자동화 동작(셸 명령어, HTTP 웹훅, LLM 프롬프트, MCP 도구 호출, 서브에이전트 평가)입니다. 훅은 JSON 입력을 받고, 종료 코드와 JSON 출력으로 결과를 전달합니다.

주요 기능: - 이벤트 기반 자동화 - JSON 기반 입력/출력 - command, http, mcp_tool, prompt, agent 훅 유형 지원 - 도구별 훅을 위한 패턴 매칭

구성

훅은 정해진 구조에 따라 설정 파일에서 구성합니다.

  • ~/.claude/settings.json - 사용자 설정(모든 프로젝트)
  • .claude/settings.json - 프로젝트 설정(공유 가능, 커밋됨)
  • .claude/settings.local.json - 로컬 프로젝트 설정(커밋되지 않음)
  • 관리형 정책 - 조직 전체 설정
  • 플러그인 hooks/hooks.json - 플러그인 범위 훅
  • 스킬/에이전트 프런트매터 - 컴포넌트 수명 동안 유지되는 훅

기본 구성 구조

{
  "hooks": {
    "EventName": [
      {
        "matcher": "ToolPattern",
        "hooks": [
          {
            "type": "command",
            "command": "your-command-here",
            "timeout": 60
          }
        ]
      }
    ]
  }
}

매처 패턴

패턴 설명 예시
정확한 문자열 특정 도구와 매칭 "Write"
정규식 패턴 여러 도구와 매칭 "Edit\|Write"
쉼표 구분 나열된 도구 중 하나와 매칭(v2.1.191+) "Write,Edit"
와일드카드 모든 도구와 매칭 "*" 또는 ""
MCP 도구 서버 및 도구 패턴 "mcp__memory__.*"

매처는 정확히 매칭됩니다(v2.1.195+). 하이픈이 포함된 식별자(예: 하이픈이 들어간 MCP 도구 이름)가 더 이상 다른 도구와 실수로 부분 문자열 매칭되지 않습니다. "Write,Edit" 같은 쉼표 구분 매처는 목록의 어떤 도구에서든 실행됩니다. 이전 빌드에서는 이런 매처가 아무 알림 없이 전혀 실행되지 않았습니다.

InstructionsLoaded 매처 값:

매처 값 설명
session_start 세션 시작 시 로드된 지침
nested_traversal 중첩 디렉터리 탐색 중 로드된 지침
path_glob_match 경로 glob 패턴 매칭으로 로드된 지침

if 조건으로 범위 좁히기(도구 인수 경로)

matcher 필드는 도구 이름("Write", "Edit|Write", "*")으로 훅을 선택합니다. 도구의 인수로 더 좁게 필터링하려면(예: 편집이 src/에 영향을 줄 때만 훅을 실행하거나, 비밀 파일 읽기를 막으려는 경우) 개별 훅 핸들러에 if 조건을 추가합니다. 이는 도구 이름 매처와 다릅니다. matcher는 어떤 도구인지를, if는 어떤 호출인지를 결정합니다.

if는 권한 규칙 구문 (ToolName(pattern))을 사용하며, 도구 이름과 그 인수를 함께 평가합니다. Read/Edit/Write의 경로 패턴은 gitignore 의미 체계를 따르며 권한 규칙과 같은 기준점을 사용합니다. .env 같은 단순 이름은 모든 깊이에서 매칭되고, src/**는 현재 디렉터리 기준, /src/**는 프로젝트 루트 기준, ~/...는 홈 디렉터리 기준이며, //...는 파일 시스템 절대 경로입니다.

if 필드는 matcher가 아니라 훅 핸들러 수준, 즉 hooks 배열 안에서 type, command와 같은 수준에 둡니다.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "if": "Edit(src/**)",
            "command": "./hooks/lint-src.sh"
          }
        ]
      },
      {
        "matcher": "Read",
        "hooks": [
          {
            "type": "command",
            "if": "Read(.env)",
            "command": "./hooks/block-secret-read.sh"
          }
        ]
      }
    ]
  }
}

유효한 if 패턴 예시: Edit(src/**)(src/ 아래 편집), Read(~/.ssh/**)(모든 SSH 키 읽기), Read(.env)(현재 디렉터리 또는 그 아래의 모든 .env), Bash(git push *)(git push 하위 명령어만).

v2.1.214 업데이트: 훅 if 조건의 단일 세그먼트 dir/** 패턴(예: Edit(src/**))은 이제 <cwd>/dir에만 매칭되며, 트리의 모든 깊이에 있는 해당 디렉터리에는 매칭되지 않습니다. 이전에는 src/**가 foo/src/**에도 매칭되었습니다. 모든 깊이에서 매칭하려면 **/dir/**를 사용하십시오. 중요: 이 범위 축소는 훅 if: 조건과 allow 규칙 자동 승인에만 적용되며, deny/ask 권한 규칙은 여전히 모든 깊이의 dir/**와 매칭됩니다.

훅 유형

Claude Code는 다섯 가지 훅 유형을 지원합니다.

명령어 훅

기본 훅 유형입니다. 셸 명령어를 실행하고 JSON stdin/stdout과 종료 코드로 통신합니다.

{
  "type": "command",
  "command": "python3 \"$CLAUDE_PROJECT_DIR/.claude/hooks/validate.py\"",
  "timeout": 60
}

Exec 형식(args)

v2.1.139에서 추가되었습니다.

셸 형식인 "command": "..." 대신, 명령어 훅은 args 배열을 사용해 execve()로 바이너리를 직접 실행할 수 있습니다. 셸 파싱이 없으므로 경로 플레이스홀더를 따옴표로 감쌀 필요가 없고, 구성이 셸 인젝션 버그에 영향을 받지 않습니다.

{
  "type": "command",
  "command": "python3",
  "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/validate.py", "--strict"],
  "timeout": 60
}

command는 항상 필수입니다. args가 설정되면 command는 실행할 실행 파일(PATH에서 확인)이고 args는 그 인수 벡터입니다. 파이프, 리디렉션, && 연결, 셸 확장이 필요하면 args를 생략(셸 형식)하고, 바이너리 하나를 인수와 함께 호출할 때는 args를 사용합니다.

HTTP 훅

v2.1.63에서 추가되었습니다.

명령어 훅과 같은 JSON 입력을 받는 원격 웹훅 엔드포인트입니다. HTTP 훅은 URL로 JSON을 POST하고 JSON 응답을 받습니다. 샌드박스가 활성화되어 있으면 HTTP 훅은 샌드박스를 거쳐 라우팅됩니다. 보안을 위해 헤더 값에 환경 변수를 보간하려면 명시적인 allowedEnvVars 목록이 필요합니다.

{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "http",
        "url": "https://my-webhook.example.com/hook"
      }]
    }]
  }
}

주요 속성: - "type": "http" -- HTTP 훅임을 나타냅니다 - "url" -- 웹훅 엔드포인트 URL - 샌드박스가 활성화되어 있으면 샌드박스를 거쳐 라우팅됩니다 - headers 값에 환경 변수를 보간하려면 명시적인 allowedEnvVars 목록이 필요합니다

프롬프트 훅

훅 내용이 Claude가 평가하는 프롬프트인, LLM 평가 방식의 훅입니다. 주로 Stop 및 SubagentStop 이벤트에서 작업 완료 여부를 지능적으로 확인하는 데 사용합니다.

{
  "type": "prompt",
  "prompt": "Evaluate if Claude completed all requested tasks.",
  "timeout": 30
}

LLM이 프롬프트를 평가하고 구조화된 결정을 반환합니다(자세한 내용은 프롬프트 기반 훅 참고).

MCP 도구 훅

v2.1.118에서 추가되었습니다.

mcp_tool 유형은 구성된 MCP 도구를 직접 호출합니다. 구성에는 셸 명령어나 URL 대신 MCP 서버와 도구 이름을 지정합니다. 검증이나 대응 로직이 이미 구성해 둔 MCP 서버에 있을 때 유용합니다.

{
  "matcher": "Edit",
  "hooks": [{
    "type": "mcp_tool",
    "server": "my-mcp-server",
    "tool": "validate_edit",
    "input": { "file_path": "${tool_input.file_path}" }
  }]
}

주요 속성: - "type": "mcp_tool" -- MCP 도구 훅임을 나타냅니다 - "server" -- 구성된 MCP 서버 이름 - "tool" -- 해당 서버에서 호출할 도구 이름 - "input" -- 도구에 전달할 선택적 인수입니다. 문자열 값은 "${tool_input.file_path}"처럼 훅의 JSON 입력에서 가져오는 ${path} 치환을 지원합니다

도구의 인수는 훅 입력에서 직접 오는 것이 아니라 input(${path} 치환 포함)에서 옵니다. MCP 서버 구성 방법은 MCP 서버 설정을 참고하십시오.

에이전트 훅

전용 에이전트를 생성하여 조건을 평가하거나 복잡한 검사를 수행하는 서브에이전트 기반 검증 훅입니다. 프롬프트 훅(단일 턴 LLM 평가)과 달리 에이전트 훅은 도구를 사용하고 여러 단계의 추론을 수행할 수 있습니다.

참고: 에이전트 훅은 실험적 기능이며 변경될 수 있습니다.

참고: v2.1.280부터 에이전트 훅은 PermissionRequest에서 실행되지 않습니다. 에이전트 훅의 응답으로는 요청을 허용하거나 거부할 수 없었기 때문입니다. 이 이벤트에서는 결정 객체를 반환하는 command 또는 HTTP 훅을 사용하십시오(프롬프트 훅의 ok: false는 PermissionRequest에 영향을 주지 않습니다).

{
  "type": "agent",
  "prompt": "Verify the code changes follow our architecture guidelines. Check the relevant design docs and compare.",
  "timeout": 120
}

주요 속성: - "type": "agent" -- 에이전트 훅임을 나타냅니다 - "prompt" -- 서브에이전트에게 맡길 작업 설명 - 에이전트는 평가를 위해 도구(Read, Grep, Bash 등)를 사용할 수 있습니다 - 프롬프트 훅과 비슷한 구조화된 결정을 반환합니다

PreToolUse

Claude가 도구 매개변수를 만든 뒤, 처리하기 전에 실행됩니다. 도구 입력을 검증하거나 수정할 때 사용합니다.

구성:

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate-bash.py"
          }
        ]
      }
    ]
  }
}

일반적인 매처: Agent, Bash, Glob, Grep, Read, Edit, Write, WebFetch, WebSearch

출력 제어: - permissionDecision: "allow", "deny", "ask", "defer" - "allow"는 권한 프롬프트를 건너뜁니다(사용자 상호 작용이 필요한 도구와 조직에서 ask로 설정한 커넥터 도구는 제외) - "deny"는 도구 호출을 막습니다 - "ask"는 사용자에게 확인을 요청하며, 프롬프트에 훅이 속한 플러그인이나 스킬의 이름이 표시됩니다(v2.1.301) - "defer"는 나중에 도구를 재개할 수 있도록 턴을 종료하며, -p를 사용한 비대화형 모드에서만 동작합니다(대화형 세션에서는 경고를 기록하고 무시합니다). 결과에는 stop_reason: "tool_deferred"가 포함됩니다. 이 값에서는 permissionDecisionReason, updatedInput, additionalContext가 모두 무시됩니다 - 훅이 무엇을 반환하든 deny 및 ask 규칙은 여전히 평가됩니다. 여러 PreToolUse 훅의 결정이 다르면 우선순위는 deny > defer > ask > allow입니다 - permissionDecisionReason: 결정에 대한 설명입니다. "ask"에서는 (Claude가 아닌) 사용자에게, "deny"에서는 Claude에게 표시되며, "allow"와 "defer"에서는 디버그 로그에만 기록됩니다 - updatedInput: 대체할 도구 입력입니다(입력 객체 전체를 대체). v2.1.300부터 Claude 자신의 입력처럼 검증되어, 알 수 없는 키는 제거되고 도구가 거부하는 입력은 호출을 거부합니다. 같은 호출에 대해 여러 PreToolUse 훅이 updatedInput을 반환하면 Claude Code는 재작성 내용을 병합하지 않으며 어떤 입력으로 도구가 실행될지 보장하지 않으므로, 특정 도구의 입력은 하나의 훅만 재작성하도록 하십시오.

PostToolUse

도구가 완료된 직후 실행됩니다. 검증, 로깅, Claude에게 컨텍스트를 다시 제공하는 용도로 사용합니다.

구성:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/security-scan.py"
          }
        ]
      }
    ]
  }
}

출력 제어: - "block" 결정은 피드백과 함께 Claude에게 프롬프트를 보냅니다 - additionalContext: Claude에게 추가되는 컨텍스트

추가 입력 필드(v2.1.119):

필드 유형 설명
duration_ms number 도구 실행 시간(밀리초)입니다. 권한 프롬프트와 PreToolUse 훅 실행에 쓴 시간은 제외됩니다. PostToolUse와 PostToolUseFailure 훅 모두에서 사용할 수 있습니다.

복구 가능한 차단(continueOnBlock, v2.1.139)

PostToolUse에서 "decision": "block"을 반환하는 command 훅은 도구 결과 옆에 reason을 추가하며, Claude는 여전히 원래 출력을 봅니다. continueOnBlock은 prompt 훅 필드입니다(command 및 agent 훅에는 없음). 기본적으로 PostToolUse에서 ok: false를 반환하는 prompt 훅은 턴을 종료하고 이유를 경고 줄로 표시합니다. prompt 훅에 "continueOnBlock": true를 설정하면 대신 이유를 Claude에게 다시 전달하고 턴을 계속하므로, 모델이 피드백을 읽고 재시도하거나 조정할 수 있습니다.

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Check this edit against our write policy (for example, read-only paths). Hook input: $ARGUMENTS",
            "continueOnBlock": true
          }
        ]
      }
    ]
  }
}

훅의 reason이 Claude가 조치할 수 있는 내용일 때(예: "이 파일은 읽기 전용이므로 다른 곳에 쓰십시오") 사용하고, 차단 시 턴 전체를 반드시 멈춰야 한다면 설정하지 마십시오.

UserPromptSubmit

사용자가 프롬프트를 제출하면 Claude가 처리하기 전에 실행됩니다. v2.1.299부터는 스킬이나 사용자 정의 명령어가 확장되기 전에 실행되므로, 프롬프트를 차단하면 해당 명령어의 ! 셸 줄도 실행되지 않습니다. UserPromptExpansion은 그 이후에 실행됩니다.

구성:

{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate-prompt.py"
          }
        ]
      }
    ]
  }
}

출력 제어: - decision: 처리를 막으려면 "block" - reason: 차단된 경우의 설명 - additionalContext: 프롬프트에 추가되는 컨텍스트

Stop 및 SubagentStop

Claude가 응답을 마칠 때(Stop) 또는 서브에이전트가 완료될 때(SubagentStop) 실행됩니다. 작업 완료 여부를 지능적으로 확인하기 위한 프롬프트 기반 평가를 지원합니다.

추가 입력 필드: Stop과 SubagentStop 훅은 모두 JSON 입력에서 last_assistant_message 필드를 받으며, 여기에는 멈추기 전 Claude 또는 서브에이전트의 마지막 메시지가 들어 있습니다. 작업 완료를 평가할 때 유용합니다.

구성:

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Evaluate if Claude completed all requested tasks.",
            "timeout": 30
          }
        ]
      }
    ]
  }
}

연속 차단 안전 상한(v2.1.143): 같은 턴에서 Stop 훅이 "decision": "block"을 반환(또는 continue: false를 설정)하는 일이 8번 연속 발생하면, Claude Code는 다음 차단을 무시하고 턴을 종료합니다. 임계값은 환경 변수 CLAUDE_CODE_STOP_HOOK_BLOCK_CAP=<integer>로 바꿀 수 있습니다(0으로 설정하면 상한이 완전히 비활성화됩니다). 이를 통해 버그가 있는 Stop 훅이 턴을 끝없이 반복하는 것을 방지합니다.

반환 필드(v2.1.163): Stop 또는 SubagentStop 훅은 hookSpecificOutput.additionalContext를 반환하여 Claude에게 피드백을 주고 오류 라벨을 표시하지 않고 턴을 계속할 수 있습니다. 이전에는 Stop 훅에서 모델에 영향을 주기가 번거로웠지만, 이제는 이전 피드백 방식(예: "decision": "block")의 오류 라벨 동작 없이 깔끔하게 컨텍스트를 주입할 수 있습니다.

{
  "hookSpecificOutput": {
    "hookEventName": "Stop",
    "additionalContext": "Reminder: run the test suite before declaring done."
  }
}

구성:

{
  "hooks": {
    "SubagentStart": [
      {
        "matcher": "code-review",
        "hooks": [
          {
            "type": "command",

    ]
  }
}

SessionStart

세션이 시작되거나 재개될 때 실행됩니다. 환경 변수를 유지할 수 있습니다.

매처: startup, resume, clear, compact, fork

v2.1.214 업데이트: 포크된 세션은 이제 출처를 "fork"로 보고합니다. 이전에는 "resume"으로 보고했습니다.

특별 기능: CLAUDE_ENV_FILE을 사용하여 환경 변수를 유지합니다(CwdChanged 및 FileChanged 훅에서도 사용 가능).

#!/bin/bash
if [ -n "$CLAUDE_ENV_FILE" ]; then
  echo 'export NODE_ENV=development' >> "$CLAUDE_ENV_FILE"
fi
exit 0

세션 범위 출력(v2.1.152): SessionStart 훅은 JSON을 반환하여 스킬을 다시 검색하고 세션 제목을 설정할 수 있습니다.

{
  "reloadSkills": true,
  "hookSpecificOutput": {
    "sessionTitle": "Payments migration"
  }
}

PreModelSwitch

Claude Code가 요청된 모델 전환을 적용하기 전에 실행됩니다. 예를 들어 /model을 실행하거나 컴포넌트가 다른 모델을 요청할 때입니다. v2.1.251 이상이 필요합니다.

매처: to_model에서 도출한, 전환 대상 모델의 정식 이름입니다. 정확한 모델(claude-opus-5)이나 정규식으로 모델 계열(.*opus.*)을 매칭합니다.

입력 필드: 공통 필드에 더해 from_model(전환 전 사용 중인 모델)과 to_model(요청된 모델)을 받습니다.

차단 가능: 예. 종료 코드 2는 전환을 차단하고 stderr를 오류로 표시하므로 세션은 현재 모델을 유지합니다. 모델 변경을 통제하거나 거부할 때 사용합니다. 예를 들어 비용에 민감한 프로젝트가 가장 비싼 모델을 쓰지 않도록 할 수 있습니다.

타임아웃: 이 이벤트는 command, http, mcp_tool의 기본 타임아웃을 30초로 낮춥니다.

구성:

{
  "hooks": {
    "PreModelSwitch": [
      {
        "matcher": ".*opus.*",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/gate-model-switch.sh"
          }
        ]
      }
    ]
  }
}

if [[ "$to_model" == *opus* ]]; then

PostModelSwitch

세션의 모델이 변경된 후에 실행됩니다. 사용자가 요청한 전환뿐 아니라 Claude Code가 스스로 수행하는 변경(예: 세션을 재개할 때 이전에 선택한 모델 복원)에서도 실행됩니다. v2.1.251 이상이 필요합니다.

매처: PreModelSwitch와 같습니다. to_model에서 도출한 정식 이름입니다.

입력 필드: 공통 필드와 함께 from_model 및 to_model을 받습니다.

차단 가능: 아니요. 전환이 이미 일어났으므로 훅은 관찰하고 대응만 할 수 있습니다.

타임아웃: 이 이벤트는 command, http, mcp_tool의 기본 타임아웃을 30초로 낮춥니다.

구성:

{
  "hooks": {
    "PostModelSwitch": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/log-model-switch.sh"
          }
        ]
      }
    ]
  }
}

#!/bin/bash
# log-model-switch.sh - 모든 모델 변경을 세션 로그에 추가

컴포넌트 범위 훅

훅은 특정 컴포넌트(스킬, 에이전트, 명령어)의 프런트매터에 연결할 수 있습니다.

SKILL.md, agent.md, command.md에서:

---
name: secure-operations
description: Perform operations with security checks
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/check.sh"
          once: true  # 스킬 프런트매터 전용: 첫 번째 실행이 성공하면 제거됨
---

지원 이벤트: 모든 훅 이벤트입니다. 서브에이전트 훅은 서브에이전트가 활성 상태일 때만 실행되며(Stop → SubagentStop), 스킬 훅은 스킬이 호출될 때 등록되어 세션의 나머지 기간 동안 활성 상태로 유지됩니다. v2.1.304부터 한 출처(프로젝트, 개인 스킬 폴더, 또는 하나의 플러그인)의 스킬은 세션당 최대 1,024개의 훅과 16,384자의 매처 문자를 등록할 수 있으며, 한도를 넘은 스킬은 훅을 하나도 등록하지 않습니다(claude --debug 로그에서 registers none of its hooks를 검색하십시오).

이를 통해 훅을 사용하는 컴포넌트 안에 훅을 직접 정의하여 관련 코드를 한곳에 모아 둘 수 있습니다.

서브에이전트 프런트매터의 훅

서브에이전트의 프런트매터에 Stop 훅을 정의하면, 해당 서브에이전트로 범위가 지정된 SubagentStop 훅으로 자동 변환됩니다. 이렇게 하면 메인 세션이 멈출 때가 아니라 해당 서브에이전트가 완료될 때만 stop 훅이 실행됩니다.

---
name: code-review-agent
description: Automated code review subagent
hooks:
  Stop:
    - hooks:
        - type: prompt
          prompt: "Verify the code review is thorough and complete."
  # 위 Stop 훅은 이 서브에이전트의 SubagentStop으로 자동 변환됨
---

워크스페이스 신뢰 필요(v2.1.218): 프로젝트 서브에이전트의 프런트매터 훅은 이제 실행되기 전에, 에이전트 파일이 위치한 폴더에 대해 워크스페이스 신뢰를 수락해야 합니다. v2.1.218 이전에는 신뢰하지 않은 폴더에서도 이 훅이 실행될 수 있었습니다. 어떤 범위가 예외인지는 서브에이전트 문서를 참고하십시오.

범위(v2.1.121+): 이제 hookSpecificOutput.updatedToolOutput은 MCP 도구뿐 아니라 모든 도구에서 적용됩니다. Bash, Edit, Read 등에 대한 PostToolUse 훅은 Claude가 보기 전에 도구 출력을 재작성할 수 있으므로, 비밀 정보 마스킹, diff 정규화, 시끄러운 명령어 출력 필터링에 유용합니다. 값은 도구의 출력 형태와 일치해야 합니다. Bash는 stdout, stderr, interrupted, isImage를 가진 객체를 반환하며, 내장 도구에서 형태가 맞지 않는 값은 무시되고 원래 출력이 사용됩니다. 예시(Bash 출력에서 ANSI 색상 코드 제거):

json { "hookSpecificOutput": { "hookEventName": "PostToolUse", "updatedToolOutput": { "stdout": "<output with ANSI escapes removed>", "stderr": "", "interrupted": false, "isImage": false } } }

retry(PermissionDenied): JSON hookSpecificOutput.retry: true를 사용하면 거부된 도구 호출을 다시 시도해도 된다고 모델에게 알릴 수 있습니다.

지원 중단(deprecated)된 PreToolUse 결정 형식: PreToolUse에서 최상위 decision 및 reason 필드는 지원 중단되었습니다. 대신 hookSpecificOutput.permissionDecision(allow / deny / ask / defer)과 permissionDecisionReason을 사용하십시오. 결정 간 우선순위는 deny > defer > ask > allow입니다. 또한 suppressOutput은 허용되지만 아무 효과가 없습니다.

terminalSequence(v2.1.141)

훅은 JSON 출력에 terminalSequence를 설정하여 원시 OSC(operating system command) 이스케이프 시퀀스를 내보낼 수 있습니다. 훅이 반환되면 호스트가 이 시퀀스를 제어 터미널에 씁니다. 별도의 TTY 없이도 데스크톱 알림, 창 제목 업데이트, 터미널 벨을 사용할 때 유용합니다.

필드 유형 설명
terminalSequence string 원시 이스케이프 시퀀스(일반적으로 OSC 9 / OSC 0 / OSC 777). 호스트 터미널에 그대로 기록됩니다.

예시: 긴 작업이 완료되면 OSC 9 데스크톱 알림을 보냅니다. ESC와 BEL은 JSON 이스케이프(\u001b, \u0007)로 쓰거나 printf와 jq로 값을 만드십시오. JSON 문자열 안의 원시 제어 바이트는 파싱에 실패합니다.

{
  "terminalSequence": "\u001b]9;Task complete\u0007"
}

Claude가 턴을 마칠 때 알림이 실행되도록 Stop 훅에 구성하십시오. 시퀀스 지원 여부는 터미널에 따라 다릅니다. iTerm2, Windows Terminal, WezTerm은 OSC 9를 지원하며 Kitty는 OSC 99를 사용합니다.

#!/usr/bin/env python3
import json
import sys
import re

BLOCKED_PATTERNS = [
    (r"\brm\s+-rf\s+/", "Blocking dangerous rm -rf / command"),
    (r"\bsudo\s+rm", "Blocking sudo rm command"),
]

def main():
    input_data = json.load(sys.stdin)

    tool_name = input_data.get("tool_name", "")
    if tool_name != "Bash":
        sys.exit(0)

    command = input_data.get("tool_input", {}).get("command", "")

            print(message, file=sys.stderr)
            sys.exit(2)  # 종료 코드 2 = 차단 오류

    sys.exit(0)

if __name__ == "__main__":
    main()

파일: .claude/hooks/security-scan.py

#!/usr/bin/env python3
import json
import sys
import re

SECRET_PATTERNS = [
    (r"password\s*=\s*['\"][^'\"]+['\"]", "Potential hardcoded password"),
    (r"api[_-]?key\s*=\s*['\"][^'\"]+['\"]", "Potential hardcoded API key"),
]

def main():
    input_data = json.load(sys.stdin)

    tool_name = input_data.get("tool_name", "")
    if tool_name not in ["Write", "Edit"]:
        sys.exit(0)

    tool_input = input_data.get("tool_input", {})
    content = tool_input.get("content", "") or tool_input.get("new_string", "")
    file_path = tool_input.get("file_path", "")

    warnings = []
    for pattern, message in SECRET_PATTERNS:
        if re.search(pattern, content, re.IGNORECASE):
            warnings.append(message)

    if warnings:
        output = {
            "hookSpecificOutput": {
                "hookEventName": "PostToolUse",
                "additionalContext": f"Security warnings for {file_path}: " + "; ".join(warnings)
            }
        }
        print(json.dumps(output))

    sys.exit(0)

if __name__ == "__main__":
    main()

예시 6: 컨텍스트 사용량 추적기(훅 쌍)

UserPromptSubmit(메시지 전)과 Stop(응답 후) 훅을 함께 사용하여 요청별 토큰 소비량을 추적합니다.

파일: .claude/hooks/context-tracker.py

#!/usr/bin/env python3
"""
Context Usage Tracker - Tracks token consumption per request.

Uses UserPromptSubmit as "pre-message" hook and Stop as "post-response" hook
to calculate the delta in token usage for each request.

Token Counting Methods:
1. Character estimation (default): ~4 chars per token, no dependencies
2. tiktoken (optional): More accurate (~90-95%), requires: pip install tiktoken
"""
import json
import os
import sys
import tempfile

# 구성
CONTEXT_LIMIT = 1000000  # Opus 5, Sonnet 5, Opus 4.8, Sonnet 4.6은 1M, Haiku 4.5는 200000 (사용 모델에 맞게 조정)
USE_TIKTOKEN = False    # 정확도를 높이려면 tiktoken 설치 후 True로 설정


def get_state_file(session_id: str) -> str:
    """Get temp file path for storing pre-message token count, isolated by session."""
    return os.path.join(tempfile.gettempdir(), f"claude-context-{session_id}.json")


def count_tokens(text: str) -> int:
    """
    Count tokens in text.

    Uses tiktoken with p50k_base encoding if available (~90-95% accuracy),
    otherwise falls back to character estimation (~80-90% accuracy).
    """
    if USE_TIKTOKEN:
        try:
            import tiktoken
            enc = tiktoken.get_encoding("p50k_base")
            return len(enc.encode(text))
        except ImportError:
            pass  # 추정 방식으로 대체

    # 문자 기반 추정: 영어 기준 토큰당 약 4자
    return len(text) // 4


def read_transcript(transcript_path: str) -> str:
    """Read and concatenate all content from transcript file."""
    if not transcript_path or not os.path.exists(transcript_path):
        return ""

    content = []
    with open(transcript_path, "r") as f:
        for line in f:
            try:
                entry = json.loads(line.strip())
                # 다양한 메시지 형식에서 텍스트 내용 추출
                if "message" in entry:
                    msg = entry["message"]
                    if isinstance(msg.get("content"), str):
                        content.append(msg["content"])
                    elif isinstance(msg.get("content"), list):
                        for block in msg["content"]:
                            if isinstance(block, dict) and block.get("type") == "text":
                                content.append(block.get("text", ""))
            except json.JSONDecodeError:
                continue

    return "\n".join(content)


def handle_user_prompt_submit(data: dict) -> None:
    """Pre-message hook: Save current token count before request."""
    session_id = data.get("session_id", "unknown")
    transcript_path = data.get("transcript_path", "")

    transcript_content = read_transcript(transcript_path)
    current_tokens = count_tokens(transcript_content)

    # 나중에 비교할 수 있도록 임시 파일에 저장
    state_file = get_state_file(session_id)
    with open(state_file, "w") as f:
        json.dump({"pre_tokens": current_tokens}, f)


def handle_stop(data: dict) -> None:
    """Post-response hook: Calculate and report token delta."""
    session_id = data.get("session_id", "unknown")
    transcript_path = data.get("transcript_path", "")

    transcript_content = read_transcript(transcript_path)
    current_tokens = count_tokens(transcript_content)

    # 메시지 전 토큰 수 불러오기
    state_file = get_state_file(session_id)
    pre_tokens = 0
    if os.path.exists(state_file):
        try:
            with open(state_file, "r") as f:
                state = json.load(f)
                pre_tokens = state.get("pre_tokens", 0)
        except (json.JSONDecodeError, IOError):
            pass

    # 차이 계산
    delta_tokens = current_tokens - pre_tokens
    remaining = CONTEXT_LIMIT - current_tokens
    percentage = (current_tokens / CONTEXT_LIMIT) * 100

    # 사용량 보고
    method = "tiktoken" if USE_TIKTOKEN else "estimated"
    print(f"Context ({method}): ~{current_tokens:,} tokens ({percentage:.1f}% used, ~{remaining:,} remaining)", file=sys.stderr)
    if delta_tokens > 0:
        print(f"This request: ~{delta_tokens:,} tokens", file=sys.stderr)


def main():
    data = json.load(sys.stdin)
    event = data.get("hook_event_name", "")

    if event == "UserPromptSubmit":
        handle_user_prompt_submit(data)
    elif event == "Stop":
        handle_stop(data)

    sys.exit(0)


if __name__ == "__main__":
    main()

예시 8: 학습 진행 기록기(SessionEnd)

각 Claude Code 세션이 끝날 때 학습한 모듈을 기록합니다. 진행 상황은 ~/.claude-howto-progress.json에 저장되며, 저장소 밖에 있으므로 git pull을 해도 덮어쓰이지 않습니다.

왜 Stop이 아니라 SessionEnd인가요? Stop은 Claude의 모든 응답 후에 실행됩니다. SessionEnd는 세션이 종료될 때 한 번 실행되므로, 세션 종료 일지 항목에 딱 맞습니다.

왜 대화형 프롬프트가 없나요? 훅은 제어 터미널 없이 실행되므로 /dev/tty를 사용할 수 없고, 훅이 사용자에게 입력을 요청할 수 없습니다. Claude Code를 실행할 때 모듈(및 선택적 메모)을 환경 변수로 전달하십시오. 예: CLAUDE_HOWTO_MODULES=06,07 claude.

파일: 06-hooks/session-end.sh

#!/usr/bin/env bash
# SessionEnd 훅: 작업한 모듈을 기록한 뒤, 학습 진행 상황을 지속적으로 추적하기 위해
# ~/.claude-howto-progress.json에 세션 기록을 추가합니다.

PROGRESS_FILE="$HOME/.claude-howto-progress.json"

# 가드: 이 저장소 안에서만 실행
if [[ "$CLAUDE_PROJECT_DIR" != *"claude-howto"* ]] && [[ "$PWD" != *"claude-howto"* ]]; then
  exit 0
fi

if [ ! -f "$PROGRESS_FILE" ]; then
  echo '{"sessions":[]}' > "$PROGRESS_FILE"
fi

DATE=$(date +"%Y-%m-%d")
TIME=$(date +"%H:%M")

# 작업한 모듈. 예: CLAUDE_HOWTO_MODULES=06,07 claude 로 실행
# 01=Slash  02=Memory  03=Skills  04=Subagents  05=MCP
# 06=Hooks  07=Plugins 08=Checkpoints 09=Advanced 10=CLI
INPUT="${CLAUDE_HOWTO_MODULES:-}"

if [ -z "$INPUT" ] || [ "$INPUT" = "skip" ]; then
  exit 0
fi

MODULES_JSON=$(echo "$INPUT" | tr ',' '\n' | tr -d ' ' | while read -r m; do
  case "$m" in
    01) echo '"01-slash-commands"' ;;
    02) echo '"02-memory"' ;;
    03) echo '"03-skills"' ;;
    04) echo '"04-subagents"' ;;
    05) echo '"05-mcp"' ;;
    06) echo '"06-hooks"' ;;
    07) echo '"07-plugins"' ;;
    08) echo '"08-checkpoints"' ;;
    09) echo '"09-advanced-features"' ;;
    10) echo '"10-cli"' ;;
    *)  echo "\"$m\"" ;;
  esac
done | paste -sd ',' -)

# 선택적 메모. 예: CLAUDE_HOWTO_NOTES="tried the pre-commit example"
NOTES="${CLAUDE_HOWTO_NOTES:-}"

# NOTES를 별도 인수로 전달하여 Python이 JSON 이스케이프를 처리하도록 함 —
# 메모에 따옴표나 백슬래시가 있어도 JSON이 깨지지 않음.
python3 - "$PROGRESS_FILE" "$DATE" "$TIME" "$MODULES_JSON" "$NOTES" <<'PYEOF'
import sys, json

path, date, time_str, modules_raw, notes = sys.argv[1], sys.argv[2], sys.argv[3], sys.argv[4], sys.argv[5]

new_session = {
    "date": date,
    "time": time_str,
    "modules": json.loads(f"[{modules_raw}]") if modules_raw else [],
    "notes": notes,
}

with open(path, 'r') as f:
    data = json.load(f)

data.setdefault('sessions', []).append(new_session)

with open(path, 'w') as f:
    json.dump(data, f, indent=2)
PYEOF

echo " Saved to $PROGRESS_FILE"

보안 고려 사항

면책 조항

사용에 따른 책임은 사용자에게 있습니다: 훅은 임의의 셸 명령어를 실행합니다. 다음 사항에 대한 책임은 전적으로 사용자에게 있습니다. - 구성한 명령어 - 파일 접근/수정 권한 - 데이터 손실 또는 시스템 손상 가능성 - 프로덕션 사용 전 안전한 환경에서의 훅 테스트

보안 참고 사항

  • 워크스페이스 신뢰 필요: statusLine 및 fileSuggestion 훅 출력 명령어는 이제 워크스페이스 신뢰를 수락해야 적용됩니다.
  • 상태 줄 터미널 크기(v2.1.153): 상태 줄 명령어 스크립트는 이제 COLUMNS 및 LINES 환경 변수를 받으므로, 터미널 너비/높이에 맞게 출력을 조정할 수 있습니다(예: [ "$COLUMNS" -lt 80 ] && short_output).
  • HTTP 훅과 환경 변수: HTTP 훅에서 헤더 값에 환경 변수를 보간하려면 명시적인 allowedEnvVars 목록이 필요합니다. 이를 통해 민감한 환경 변수가 원격 엔드포인트로 실수로 유출되는 것을 방지합니다.
  • 관리형 설정 계층 구조: 이제 disableAllHooks 설정은 관리형 설정 계층 구조를 따르므로, 조직 수준 설정으로 개별 사용자가 재정의할 수 없는 훅 비활성화를 강제할 수 있습니다.
  • PowerShell 자동 승인(v2.1.119): PowerShell 도구 명령어도 Bash와 마찬가지로 권한 모드에서 자동 승인될 수 있습니다. PowerShell 기반 셸 도구로 Claude Code를 실행하는 Windows 사용자도 동일한 동작을 얻습니다.
  • Bash 단순 환경 변수 자동 승인 차단(v2.1.145): v2.1.145 이전에는 FOO=bar somecommand 형태의 Bash 명령어(허용 목록에 없는 명령어 앞에 단순 변수 할당을 붙인 형태)가, 허용 목록에 FOO=bar만 있어도 자동 승인될 수 있었습니다. v2.1.145에서 이 문제가 수정되어 이런 명령어는 이제 권한 프롬프트를 거칩니다. 암묵적 허용에 의존하던 스크립트는 프롬프트가 표시되기 시작하므로, 변수 할당만이 아니라 전체 명령어를 포함하는 Bash(...) 권한 규칙으로 명시적으로 다시 허용하십시오.

훅 로그를 자세히 보려면 디버그 플래그와 함께 Claude를 실행합니다.

claude --debug

상세 모드

Claude Code에서 Ctrl+O를 사용하면 상세 모드가 활성화되어 훅 실행 진행 상황을 볼 수 있습니다.

훅을 독립적으로 테스트하기

# 샘플 JSON 입력으로 테스트
echo '{"tool_name": "Bash", "tool_input": {"command": "ls -la"}}' | python3 .claude/hooks/validate-bash.py

# 종료 코드 확인
echo $?

훅 실행 세부 정보

항목 동작
타임아웃 command/http/mcp_tool은 기본 600초(prompt는 30초, agent는 60초)이며, 훅별로 구성할 수 있습니다
병렬 처리 매칭되는 모든 훅이 병렬로 실행됩니다. v2.1.302부터 한 이벤트에서 prompt 또는 agent 훅은 최대 12개까지만 동시에 실행되고 나머지는 차례를 기다립니다.
중복 제거 동일한 훅 명령어는 중복 제거됩니다
환경 Claude Code의 환경에서 현재 디렉터리를 기준으로 실행됩니다

문제 해결

훅이 실행되지 않음

  • JSON 구성 구문이 올바른지 확인합니다
  • 매처 패턴이 도구 이름과 일치하는지 확인합니다
  • 스크립트가 존재하고 실행 가능한지 확인합니다: chmod +x script.sh
  • claude --debug를 실행하여 훅 실행 로그를 확인합니다
  • 훅이 (명령어 인수가 아니라) stdin에서 JSON을 읽는지 확인합니다

훅이 예기치 않게 차단함

  • 샘플 JSON으로 훅을 테스트합니다: echo '{"tool_name": "Write", ...}' | ./hook.py
  • 종료 코드를 확인합니다: 허용은 0, 차단은 2여야 합니다
  • stderr 출력을 확인합니다(종료 코드 2일 때 표시됨)

JSON 파싱 오류

  • 명령어 인수가 아니라 항상 stdin에서 읽습니다
  • (문자열 조작이 아닌) 올바른 JSON 파싱을 사용합니다
  • 누락된 필드를 적절히 처리합니다

설치

1단계: 훅 디렉터리 만들기

mkdir -p ~/.claude/hooks

2단계: 예시 훅 복사하기

cp 06-hooks/*.sh ~/.claude/hooks/
chmod +x ~/.claude/hooks/*.sh

3단계: 설정에서 구성하기

~/.claude/settings.json 또는 .claude/settings.json을 위에 나온 훅 구성으로 편집합니다.
