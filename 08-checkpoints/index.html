체크포인트 및 되감기

체크포인트를 사용하면 Claude Code 세션에서 대화 상태를 저장하고 이전 시점으로 되돌릴 수 있습니다. 이는 다양한 접근 방식을 실험하거나, 실수를 복구하거나, 여러 해결 방법을 비교하는 데 매우 유용합니다.

개요

체크포인트는 대화 상태를 저장하고 이전 시점으로 되돌릴 수 있게 해주는 기능입니다. 이를 통해 안전하게 다양한 접근 방식을 실험하고 탐색할 수 있습니다. 체크포인트에는 다음이 포함됩니다:

  • 모든 메시지 기록
  • 파일 수정 내역
  • 도구 사용 기록
  • 세션 컨텍스트

체크포인트는 다양한 접근 방식을 탐색하거나, 실수를 복구하거나, 대안들을 비교할 때 매우 유용합니다.

핵심 개념

개념 설명
체크포인트 메시지, 파일, 컨텍스트를 포함한 대화 상태의 스냅샷
되감기(Rewind) 체크포인트 시점으로 돌아가 이후 변경 사항을 폐기
브랜치 포인트 여러 접근 방식을 탐색하기 위한 기준 체크포인트

체크포인트 접근 방법

체크포인트는 두 가지 방법으로 접근할 수 있습니다:

키보드 단축키 사용

Esc 키를 두 번 누르면(Esc + Esc) 체크포인트 인터페이스가 열리며 저장된 체크포인트를 탐색할 수 있습니다.

슬래시 명령어 사용

빠른 접근을 위해 /rewind 명령어(별칭: /checkpoint, /undo)를 사용할 수 있습니다:

# 되감기 인터페이스 열기
/rewind

# 별칭 사용
/checkpoint

되감기 옵션

되감기를 수행하면 다음 6가지 옵션이 제공됩니다:

  1. 코드와 대화 복원 -- 파일과 메시지를 해당 체크포인트 상태로 모두 복원
  2. 대화만 복원 -- 메시지만 되돌리고 파일은 현재 상태 유지
  3. 코드만 복원 -- 파일만 되돌리고 대화 기록은 유지
  4. 여기서부터 요약 -- 선택 시점 이후의 대화를 AI가 생성한 요약으로 압축하여 컨텍스트 공간을 확보. 이전 메시지는 유지되며 디스크 파일은 변경되지 않음. 원본 메시지는 세션에 보존됨. 필요 시 특정 주제 중심으로 요약 가능
  5. 여기까지 요약 -- 반대 방향의 요약: 선택 시점 이전의 모든 내용을 AI가 생성한 요약으로 압축하고, 이 시점 이후의 메시지는 그대로 유지. "여기서부터 요약"과 함께 사용하면 컨텍스트 창을 양방향으로 원하는 부분만 압축 가능. 디스크 파일은 변경되지 않으며 원본 메시지는 세션 기록에 보존됨
  6. 취소 -- 작업을 취소하고 현재 상태로 복귀

참고: 대화를 복원하거나 여기서부터 요약을 선택하면 선택한 메시지의 원본 프롬프트가 입력창에 복원되어 다시 전송하거나 수정할 수 있습니다. 여기까지 요약을 선택하면 입력창이 빈 상태로 대화의 끝에 머무릅니다.

팁: 되감기 후 종료하기 전에 Claude에게 프롬프트를 하나 보내십시오. Claude Code는 되감은 대화를 그 프롬프트와 함께 저장하므로, 먼저 종료하면 되감았던 메시지가 다시 돌아올 수 있습니다. 이를 다시 제거하려면 /rewind를 실행하고 같은 프롬프트를 선택한 뒤 대화만 복원을 선택하십시오. 복원된 파일은 되감기 직후 상태로 유지됩니다.

/clear는 더 이상 강한 경계가 아님 (v2.1.191+): /rewind는 /clear를 실행하기 전에 만들어진 체크포인트에서도 재개할 수 있습니다. 대화를 지워도 그 이전 상태가 영구적으로 폐기되지 않으므로, 이전 코드나 컨텍스트가 다시 필요하면 clear를 넘어 되감을 수 있습니다.

자동 체크포인트

Claude Code는 자동으로 체크포인트를 생성합니다:

  • 모든 사용자 입력마다 체크포인트 생성
  • 영구 저장: 체크포인트가 대화와 함께 저장되므로 세션을 재개한 후에도 /rewind를 사용할 수 있음
  • 자동 정리: 30일 후 자동 삭제

따라서 몇 분 전부터 며칠 전까지 모든 시점으로 되돌아갈 수 있습니다.

사용 사례

시나리오 워크플로
다양한 접근 방식 탐색 저장 → A 시도 → 저장 → 되감기 → B 시도 → 비교
안전한 리팩터링 저장 → 리팩터링 → 테스트 → 실패 시 되감기
A/B 테스트 저장 → A 설계 → 저장 → 되감기 → B 설계 → 비교
실수 복구 문제 발견 → 마지막 정상 상태로 되감기

체크포인트 사용 방법

확인 및 되감기

Esc를 두 번 누르거나 /rewind를 입력하면 체크포인트 브라우저가 열립니다. 시간순으로 모든 체크포인트가 표시되며 원하는 시점을 선택해 되돌릴 수 있습니다.

체크포인트 상세 정보

각 체크포인트에는 다음 정보가 포함됩니다: - 생성 시간 - 수정된 파일 목록 - 대화 메시지 수 - 사용된 도구 목록

실전 예시

예시 1: 다양한 접근 방식 탐색

User: API에 캐싱 레이어를 추가해줘

Claude: Redis 캐싱을 API에 추가하겠습니다...
[A 시점 체크포인트 생성 후 변경 수행]

User: 아니, 인메모리 캐싱으로 해보자

Claude: 다른 접근 방식을 위해 되감기합니다...
[Esc+Esc로 A 체크포인트로 되감기]
[인메모리 캐싱 적용]

User: 이제 두 방식 비교할 수 있겠다

예시 2: 실수 복구

User: 인증 모듈을 JWT로 리팩터링해줘

Claude: 인증 모듈을 리팩터링합니다...
[대규모 변경 수행]

User: 잠깐, OAuth가 깨졌어. 되돌리자

Claude: 리팩터링 이전 상태로 되감겠습니다...
[리팩터링 이전 체크포인트로 복귀]

User: 이번엔 더 안전하게 해보자

예시 3: 안전한 실험

User: 함수형 스타일로 다시 작성해보자
[실험 시작 전 체크포인트 생성]

Claude: 함수형 스타일로 변경 중...

User: 테스트 실패했어. 되돌리자
[체크포인트로 복귀]

Claude: 이전 상태로 복원했습니다. 다른 접근을 시도해보겠습니다.

예시 4: 브랜치 비교

User: 두 가지 DB 설계를 비교하고 싶어
[시작 체크포인트]

Claude: 첫 번째 설계 구현...
[스키마 A 구현]

User: 다시 돌아가서 두 번째 방식도 해보자
[시작 체크포인트로 되감기]

Claude: 스키마 B 구현...
[스키마 B 구현]

User: 이제 두 가지 비교 가능

체크포인트 보관 정책

Claude Code는 체크포인트를 자동 관리합니다:

  • 모든 사용자 입력마다 자동 생성
  • 최대 30일간 보관
  • 오래된 체크포인트는 자동 삭제

워크플로 패턴

탐색을 위한 브랜칭 전략

여러 접근 방식을 비교할 때:

1. 초기 상태 → 체크포인트 A
2. 방법 1 시도 → 체크포인트 B
3. A로 되감기
4. 방법 2 시도 → 체크포인트 C
5. B와 C 비교
6. 최종 선택 후 진행

안전한 리팩터링 패턴

큰 변경을 할 때:

1. 현재 상태 → 자동 체크포인트
2. 리팩터링 시작
3. 테스트 실행
4. 성공 → 계속 진행
5. 실패 → 되감기 후 다른 접근 시도

모범 사용법

체크포인트는 자동 생성되므로 별도 저장 없이 작업할 수 있습니다. 하지만 다음 원칙을 권장합니다:

효과적인 사용법

✅ 권장 - 되감기 전 체크포인트 목록 확인 - 다른 방향을 실험할 때 rewind 활용 - 여러 접근 방식 비교에 활용 - 각 옵션의 의미 정확히 이해

❌ 비권장 - 체크포인트를 코드 저장소처럼 의존 - 외부 파일 변경 추적 용도로 사용 - Git 커밋 대체 수단으로 사용

구성(Configuration)

체크포인트는 Claude Code의 기본 내장 동작이며, 별도의 설정 없이 자동으로 활성화됩니다. 모든 사용자 입력마다 자동으로 체크포인트가 생성됩니다.

체크포인트 동작은 두 가지 설정으로 제어합니다. 하나는 스냅숏 생성 여부, 다른 하나는 보관 기간입니다:

{
  "fileCheckpointingEnabled": true,
  "cleanupPeriodDays": 30
}
설정 기본값 효과
fileCheckpointingEnabled true 각 편집 전에 파일 스냅숏을 만들어 /rewind로 복원할 수 있게 함. v2.1.119+ 필요. /config에서 Rewind code (checkpoints)로 표시됨. 대응 환경 변수: CLAUDE_CODE_DISABLE_FILE_CHECKPOINTING
cleanupPeriodDays 30 세션 기록 및 체크포인트를 보관하는 일수

Claude Code는 최근 100개 체크포인트의 스냅숏만 보관하며, 그보다 오래된 것은 보관 기간 안이라도 삭제됩니다.

v2.1.117 업데이트: cleanupPeriodDays는 이제 체크포인트뿐만 아니라 여러 디스크 캐시의 보관 기간을 관리합니다(아래는 일부이며, 세션 기록, file-history/, plans/, debug/, paste-cache/ 등도 포함됩니다):

  • 세션 체크포인트
  • ~/.claude/tasks/ — 영구 작업 리스트
  • ~/.claude/shell-snapshots/ — 셸 환경 스냅샷
  • ~/.claude/backups/ — ~/.claude.json의 이전 버전(최신 5개 유지)

하나의 설정값으로 이 디렉터리들이 동일한 보관 기간 기준으로 정리됩니다.

제한사항(Limitations)

체크포인트에는 다음과 같은 제한이 있습니다:

  • Bash로만 변경한 파일은 추적되지 않음 - Claude가 파일 편집 도구로 한 번 편집한 파일이라면, 이후 Bash 명령어가 그 파일에 가한 변경도 /rewind로 되돌릴 수 있지만, Bash 명령어로만 변경된 파일은 추적되지 않음. v2.1.309부터 sed -i도 다른 Bash 편집과 동일하게 취급됨
  • 외부 변경은 추적되지 않음 - Claude Code 외부(에디터, 터미널 등)에서 발생한 변경은 기록되지 않음
  • 버전 관리 시스템 대체 불가 - 영구적이고 감사 가능한 변경 이력은 Git을 사용해야 함
  • 서브에이전트 편집은 복원되지 않음 - 대화에서 Claude가 아직 편집하지 않은 파일을 서브에이전트가 편집하면 추적되지 않으므로 /rewind는 이를 그대로 둠(git으로 되돌려야 함). 예외적으로 포그라운드 context: fork 스킬의 편집은 메인 세션과 마찬가지로 복원됨

v2.1.216 업데이트: /rewind는 더 이상 추적 경로의 심볼릭 링크나 하드 링크를 통해 파일을 복원하거나 삭제하지 않습니다. 추적 경로가 심볼릭 링크나 하드 링크로 해석되면 링크를 따라가지 않고 건너뛰며, 이 이유로 건너뛴 경로 수를 보고합니다.

문제 해결(Troubleshooting)

체크포인트가 보이지 않음

문제: 예상한 체크포인트가 없음

해결 방법: - 체크포인트가 정리되었는지 확인 - 디스크 공간 확인 - cleanupPeriodDays 값이 충분히 큰지 확인 (기본 30일)

되감기 실패

문제: 체크포인트로 되돌아갈 수 없음

해결 방법: - 커밋되지 않은 변경 사항 충돌 여부 확인 - 체크포인트 손상 여부 확인 - 다른 체크포인트로 되감기 시도

Git과의 통합

체크포인트는 Git을 대체하지 않고 보완하는 기능입니다:

기능 Git 체크포인트
범위 파일 시스템 대화 + 파일
지속성 영구적 세션 기반
세분화 커밋 단위 모든 시점
속도 상대적으로 느림 즉시
공유 가능 제한적

둘을 함께 사용하는 것이 권장됩니다: 1. 빠른 실험에는 체크포인트 사용 2. 확정된 변경은 Git 커밋 사용 3. Git 작업 전 체크포인트 생성 4. 성공한 상태를 Git에 저장

빠른 시작 가이드(Quick Start Guide)

기본 워크플로

  1. 일반적으로 작업 - Claude Code가 자동으로 체크포인트 생성
  2. 되돌리고 싶을 때 - Esc 두 번 또는 /rewind 사용
  3. 체크포인트 선택 - 목록에서 원하는 시점 선택
  4. 복원 방식 선택 - 코드와 대화 복원, 대화만 복원, 코드만 복원, 여기서부터 요약, 여기까지 요약, 취소 중 선택
  5. 작업 계속 - 해당 시점에서 다시 작업 진행

키보드 단축키

  • Esc + Esc - 체크포인트 브라우저 열기
  • /rewind - 체크포인트 접근 명령어
  • /checkpoint, /undo - /rewind의 별칭

되감기를 언제 해야 하는가: 컨텍스트 모니터링

체크포인트는 되돌릴 수 있게 해주지만, 언제 되돌려야 하는지도 중요합니다. 대화가 길어질수록 Claude의 컨텍스트 윈도우가 차게 되고, 모델 성능이 점진적으로 저하될 수 있습니다. 이때 사용자는 인지하지 못한 상태에서 품질이 낮아진 결과를 기반으로 코드를 생성할 수 있습니다.

cc-context-stats는 이를 해결하기 위해 Claude Code 상태바에 실시간 컨텍스트 구간 표시를 제공합니다. 컨텍스트를 세 구간으로 나누어 보여줍니다:

  • Plan (초록): 안전한 계획 및 개발 단계
  • Code (노랑): 새로운 계획 시작은 피해야 하는 단계
  • Dump (주황): 마무리하고 되감기가 필요한 단계

이 구간이 변경되면 체크포인트를 만들고 새로 시작하는 것이 권장됩니다.

요약(Summary)

체크포인트는 Claude Code의 자동 기능으로, 작업을 잃지 않고 다양한 접근 방식을 안전하게 실험할 수 있게 해줍니다. 모든 사용자 입력마다 자동으로 체크포인트가 생성되므로 언제든지 이전 시점으로 되돌릴 수 있습니다.

핵심 장점: - 여러 접근 방식을 자유롭게 실험 가능 - 실수 발생 시 빠른 복구 - 다양한 해결책 비교 가능 - Git과 안전하게 함께 사용 가능

중요: 체크포인트는 Git을 대체하지 않습니다. 빠른 실험에는 체크포인트를, 확정된 변경에는 Git을 사용하세요.
